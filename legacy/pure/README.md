## AI 对话

侧栏「对话」支持 DeepSeek Flash 和 GPT-4.1，模型随当前工作区权限与服务配置显示。右键历史对话，可行内重命名、删除并撤销；操作其他对话不会切走当前内容。新对话在第一轮完整回复后由同一模型总结标题，手动名称优先，失败保留临时标题；自动命名不额外扣积分。

选中文本节点后，其下方显示与图片、视频同类的 AI 生成输入区；完整回复后直接更新原节点，可撤销。不显示右侧对话栏及“替换文字／新建文本节点”按钮，等待期间手动修改的文字不会被自动覆盖。独立对话仍通过「放入画布」采用回答。详见 `交付/对话菜单与画布直接改写-20261107.md` 和 `交付/对话右键菜单与自动标题-20261107.md`。

## 接入 GPU 实例
1. 在 Linux GPU 实例运行脚本。安装器自动识别 NVIDIA/CUDA 或 AMD/ROCm、单卡显存、容器 CPU/内存限额和磁盘；按所选模型检查资源。MiniMax H3 当前采用保守的单卡 96 GiB 显存、128 GiB 内存基线；Breeze 使用 12 GiB 显存、16 GiB 内存基线。多个显卡的显存不直接相加。
2. 在网站「设置 → GPU 实例 → 接入GPU实例」确认名称并勾选 MiniMax H3、Breeze TTS 2 或两者。默认名称按弗淼001、弗淼002递增。复制生成的命令，在实例终端执行。配对码 30 分钟有效，安装只准备所选模型。
3. 先扫描旧部署、HF／魔搭缓存、常见模型目录和数据挂载盘，按大小与 SHA-256 校验，包括改名文件、缓存软链接和未下载完的文件；源码和 Python／GPU 运行环境也检查版本及兼容性。有效文件复用，只补缺失或损坏部分。需要下载时再测速同版本的魔搭、Hugging Face、HF 镜像，换源续传后校验内容。H3 标准权重约 139.73 GB，Breeze 约 7.68 GB。终端显示扫描、校验、下载进度；按 Ctrl+C 仅退出显示，后台继续；自动化可设置 `FUMIAO_NO_FOLLOW=1`。
4. 魔搭优先将权重保存到 `/mnt/workspace/.fumiao/models`；按持久配额和实际余量逐文件分配，优先完整保存 Breeze，再尽量保留 H3。放不下的文件使用临时磁盘，下次只补缺失部分。磁盘配额不足会保留断点并调整位置，不删除用户文件腾空间。临时和持久空间均不足时停止并说明所缺容量。
5. 节点主动经 HTTPS 领取任务。新接入的双模型实例会检查每张显卡、系统内存、原生显存限额能力及实时余量；满足条件时各开一个视频和语音执行通道，否则串行切换。两通道有独立任务与进度；不会把多卡显存相加，也不会让两个任务共用同一任务租约。管理员的完成后下线、断开及移除作用于整个实例。服务端口仅绑定实例本地。
6. 默认工作目录为可写的 `/mnt/workspace/fumiao-worker`，其他 Linux 环境回退用户数据目录；主日志为该目录下的 `state/worker.log`，并行通道日志在 `state/lanes/<模型>/worker.log`。已成功接入且凭据仍有效时，原命令可恢复同一节点，接入码过期不影响已绑定节点重连；被撤销的节点不能恢复。运行中的实例再次执行安装命令只做缓存审计，不覆盖运行代码或凭据。更新运行中的旧实例需先等待任务结束并停止该工作进程，再执行新命令。
7. 可通过 `FUMIAO_HOME`、`FUMIAO_CACHE_ROOT`、`H3_CACHE`、`BREEZE_HOME` 调整路径；额外扫描路径用 `FUMIAO_SEARCH_ROOTS`，临时磁盘用 `FUMIAO_TEMP_ROOTS`（多路径以冒号分隔）。自定义持久根目录用 `FUMIAO_PERSIST_ROOT`，已确认的配额可设 `FUMIAO_PERSIST_QUOTA_BYTES`。仅检查缓存可用 `bash /tmp/fumiao-install.sh --audit-only --models minimax-h3,breeze-tts-2`。

Colab 可使用 `agent/colab.ipynb`（发布后为 `/connect/colab.ipynb`）：挂载 Drive、输入网站接入命令、安装完成后同步云端并重新挂载。脚本检测已挂载的 Drive，将权重保存在 `MyDrive/FumiaoAIGC`，本地执行副本与 Python 环境、凭据、任务数据保持在实例本地。只扫描该专用 Drive 目录及用户明确指定的缓存目录。Drive 的挂载容量不能替代真实云端配额；笔记本的缓存上限应不超过实际剩余空间。Drive 写入空间不足时保留已校验的本地副本，并明确记录未持久化的文件；已有模型不删除。重建环境后重新挂载 Drive，再使用新的接入命令即可复用权重。

缓存复用、持久分层和双模型调度的设计见 `交付/GPU缓存复用与并行调度-20261106.md`。2026-11-07 已完成 AMD 真机双模型并发、完整恢复和 768 档 15 秒图生视频验收，并上线安装可靠性修复。19 个文件共约 147.41 GB 验证通过，约 95.9 GB 位于持久目录；新环境仍需补齐约 51.51 GB 临时权重及运行环境。结果见 `交付/AMD双模型验收-20261107/验收记录.md`。

## 语音生成

## 工作区

侧栏 Logo 下方选择个人空间或团队空间。个人空间的资产、任务和画布仅本人可访问，管理员也不能直接读取其他人的个人内容。团队成员共享该空间内容；只有管理员可在“设置 → 团队空间”创建、重命名团队并分配成员。管理员不必成为成员即可进入所有团队空间。账户直接创建、密码修改仍在“成员管理”；邀请码单独在“设置 → 邀请码”管理。

现有共享数据首次迁入“默认团队”，保留现有成员的访问权限；新建账户默认进入个人空间；通过邀请码注册时可自动加入并默认进入邀请码指定的团队，同时保留个人空间。迁移在事务内执行并记录版本，重复启动不会重新加入已移除成员或重复创建团队。工作区标识跟随每个标签页的请求，草稿按账户与工作区分别保存；画布跳转携带空间，直接打开项目链接则以项目所属空间为准。撤销成员权限后，素材读取和已有下载链接都会重新校验权限。

GPU 资源池、OpenAI 配置及总计 20 GB 容量继续全局共用。任务计时考虑全局队列，但列表、收藏和详情只返回当前空间内容。生成结果始终保留提交时的空间；移除创建者不会改变团队作品归属。跨空间参考图、原版本或画布素材引用会被拒绝；暂不提供移动资产或删除工作区入口。

服务端实现：`workspace_access.py`、`workspace_api.py`；隐私及迁移验收：`.venv/bin/python tests/workspaces.py`。生产数据库副本迁移演练见 `work/workspaces-20261105/migration-proof.json`；生产本身尚未迁移。发布前备份数据库和媒体，使用独立 release 切换，并保留兼容新表结构的回滚版本；不要将旧版无列名的媒体插入语句直接回滚到已迁移数据库。GPU 噪点修复仍单独待真实出片验收，本工作区版本不能顺带宣称该修复已验证。

## 生成与存储
创作页提供六种画幅预设及 480/768 两档。像素对齐模型的 32 像素网格，宽银幕高档控制总像素量，以作品旁显示的实际宽高为准。成片 24 fps，5/10/15 秒档对应 124/243/362 帧。最多上传 9 张有序参考图片，每张上传文件最大 16 MiB。支持 JPG/JPEG、PNG、WebP、HEIC/HEIF、AVIF、TIFF、BMP、GIF；服务器将额外格式转换为标准 JPEG/PNG，动态图和多页图片使用首帧，HEIF 使用主图。新导入图片最多 6400 万像素，超出模型的 3200 万像素限制时自动等比缩小。转换后按实际文件大小计入配额。

参考图和成片总配额按十进制 20 GB 计，排队或运行任务预留最多 64 MiB；全局余量扣除预留空间。剩余 4 GB、1 GB 分别触发两级提示。管理员能看到整机磁盘剩余容量。媒体 ID 与数据库记录不依赖文件路径。当前使用本机磁盘，COS 适配器位于 storage.py，默认关闭。启用私有 COS 需要安装 cos-python-sdk-v5、配置 FUMIAO_STORAGE=cos、FUMIAO_COS_BUCKET、FUMIAO_COS_REGION、FUMIAO_COS_ID、FUMIAO_COS_KEY。切换前需按相同 ID 迁移并校验现有对象（studio/ 前缀）。在线读请求先鉴权，再换取短时签名 URL。

## OpenAI 图片生成

创作页的类型菜单支持视频与图片切换。图片固定使用 `gpt-image-2.6-sunburst`，界面名 `gpt-image-2.6`，支持文字和最多 9 张参考图、六种画幅、1K/2K、草稿/标准/高清质量，每次生成 1 张 PNG。

密钥只放在服务器的 `FUMIAO_DATA/openai.env`（生产为 `/srv/fumiao/data/openai.env`），环境变量名 `OPENAI_API_KEY`，文件归服务用户所有、权限 0600。不会通过网页/API 回传，也无需魔搭 GPU。管理员可在「设置 → 图片生成」启停、测试连接、打开平台用量。API 项目余额以 OpenAI 平台为准。

任务持久化到同一个 SQLite 队列，但由服务器独立线程处理；GPU 节点只领取视频。生成图计入 20 GB 共享空间，可直接用作视频参考图。队列去重、预留空间和引用保护覆盖图片；网络超时或服务重启后的不确定请求不自动重试，以免重复计费。部署时应先等待运行中的图片任务结束。

离线验收：`.venv/bin/python tests/image_generation.py`（独立临时数据库和模拟 OpenAI 服务，不消耗额度）。


## Muse

视频、图片和画布均可选 Muse。按已确认方案使用原生分辨率：图片五种常用比例，视频横/竖屏和 5/6/8/10 秒、默认 6 秒；成品保存真实尺寸和时长。Muse2API 的规格字段会转换成提示词要求，界面不会把它们当成成品保证。

独立队列在 Muse 未配置、离线或没有账号时保留排队。已拿到上游任务号后只继续查询/下载，不重复生成；提交是否被接受不确定时停止自动重发，标为待核对失败。GPU 和 OpenAI 分别只处理自己的模型。管理员在“设置 → 模型管理”分别开放或关闭四个模型。关闭模型拒绝新提交，已有排队任务等待重新开放，正在执行的任务继续完成；前端置灰和服务端派单均执行此规则。OpenAI 连接检测保留在“设置 → OpenAI”。

配置放在服务端 `FUMIAO_DATA/muse.env`，权限 0600：`FUMIAO_MUSE_URL`、`FUMIAO_MUSE_KEY`（使用现有 Muse2API Key），可选 `FUMIAO_MUSE_PUBLIC_URL`。默认地址 `https://backend.nvmes.com/muse`，腾讯云工作台通过 `http://127.0.0.1:18610` 调用同机 Muse 服务。隔离测试可设置 `FUMIAO_MUSE_AUTOSTART=0`。密钥不会进入浏览器、状态 API 或发布包。

`tests/muse_generation.py` 覆盖排队/分流/重启续查/原生规格/工作区权限/不重复提交等。真实图与 6 秒视频已出片并在浏览器完整播放，详情见 `交付/Muse接入与验收-20261106.md`。Muse2API 保留其自身的任务与媒体记录，本轮没有清理该独立服务的数据；弗淼的 20 GB 额度统计其自身资产。

## 多选与收藏

资产页卡片左上角勾选进入多选；顶部可全选、删除、收藏或取消收藏。收藏夹按当前账号独立保存，源资产仍在团队共享库。图片、视频、上传参考图与详情页均支持收藏。单次批量操作最多200项。

批量删除在一个事务中检查全部资产的所有权、运行状态和引用关系；冲突则整批不删除。若被引用图片及其全部关联任务都在选择范围内，可以一起删除。数据库外键会同步清理所有用户的失效收藏。

验证：`.venv/bin/python tests/library_management.py`，使用隔离数据库，不修改正式资产。


## 批量下载与多选显示

默认状态不显示卡片勾选框。进入多选后，鼠标悬停的卡片和已选卡片显示勾选框，键盘焦点同样可见；触屏直接点击卡片切换选中状态。顶部「下载」将所选已完成作品和上传图片按原始字节打包为 ZIP。

下载采用服务端流式 ZIP/ZIP64，无完整压缩包落盘；准备接口返回15分钟有效、绑定当前账户且仍需登录的下载地址。视频和图片不重新压缩。测试包括 ZIP 内容/CRC、跨账户与过期链接拒绝、文件删除竞态、读取块大小和中断资源清理。

验证：`.venv/bin/python tests/batch_download.py`。

## 耗时记录与预估

创作框按当前参数显示预估，任务卡片、队列和详情显示动态剩余时间，完成后可查看处理/排队/准备/生成/回传等耗时。样本不足或新硬件尚未校准时显示数据积累中。历史作品显示的是历史总等待。

`timing.py` 管理每次尝试的计时和预测；`job_runs` 保留不含提示词的参数快照与原始预测。估算按具体GPU与推理配置隔离，并在有足够记录后校准本实例速度。新的接入包含 `job_progress.py`；现有旧代理继续兼容，其阶段采用服务端上报观察时间。

验证：`tests/timing_estimates.py` 覆盖阶段计时、重试、并行队列、硬件/运行环境隔离、同规格实例不同速度、旧数据标记与倒计时过期。`tests/image_generation.py` 和 `tests/acceptance.py` 覆盖实际图片保存与MP4回传路径的计时记录。


## 单图视频的方向与画幅

不上传图片时使用文生视频；1张图片作为首帧，先按目标尺寸等比居中裁切，再进入 FL2VA 图生视频；2–9张图片继续走 R2V 多参考图流程。任务内输入统一应用 EXIF 方向并保存成真实 PNG，服务器上的原始上传文件保留。输出除宽高/帧数/解码检查外，还拒绝非零旋转元数据。播放器按视频实际宽高比布局。

验证：`.venv/bin/python tests/video_orientation.py`，覆盖8种EXIF方向、重复规范化、单图首帧接线、不同画幅、多参考图及 MP4 旋转元数据。


## 共享画布

工作台“画布”进入独立的节点工作区。所有登录成员可创建、查看和编辑，创建者或管理员可删除。文本、图片、视频、便签可拖动和框选；参考连线按顺序传递文本正文和图片。视频与图片沿用现有模型、参数、容量、队列及耗时统计。图片服务关闭时不能在画布提交图片任务，已有图片仍可作为素材。

节点生成经 `/api/canvases/{id}/nodes/{node}/runs` 在同一事务创建现有 jobs 记录及画布关联，固定输入快照；重发同一 UID 不重复消费。刷新只恢复状态，不提交生成。删除节点或画布不会删除团队素材，也不会取消已提交任务；结果仍保留在资产库。素材删除会检查画布引用。

文档按 revision 自动保存；浏览器保留未保存草稿。冲突时禁止静默覆盖，可下载本地副本后重新载入。视口和选中状态不影响共享文档。撤销只作用于编辑操作，不逆转后台任务。当前每张画布最多 200 节点、600 条连线，团队最多 200 个项目。

前端源码位于 `canvas/src`，React + TypeScript + React Flow 独立构建，原工作台无需迁移。`npm ci --prefix canvas && npm run build --prefix canvas` 生成 `static/canvas.js` 和 `static/canvas.css`；`static/canvas.html` 为独立入口，服务端新增 `canvas_api.py` 和共享任务模块 `generation.py`。开发预览须同步三个 canvas 静态文件到 `preview-jimeng/static` 并在后端变更后重启预览。

验收：`.venv/bin/python tests/canvas_management.py` 使用临时数据库与模拟图片服务，验证权限、并发保存冲突、连线校验、输入冻结、幂等、结果回填、引用保护及删除语义，不消耗生产额度。既有生成、收藏、下载等分别运行原测试。


## 队列估算

队列按真实 FIFO 领取顺序模拟每个在线可用实例的执行槽；使用实际硬件规格、模型模式、画幅、时长、参考数量和已加载模型状态。每次刷新会根据运行进度、完成、取消及实例上下线重算后续等待。多实例不采用统一平均速度，也不把一台多卡机器自动当成多个并发槽。

主界面显示单个估计时间（如“约 4 分 30 秒”），内部保留不确定边界。缺少可靠样本时显示“观测中”；可利用同规格、同参数的进行中采样数据作临时估算，完成后再转入成功历史。图片 API 保持独立串行队列。

验证：`tests/queue_planning.py` 覆盖不同实例速度、并行领取次序、模型切换、未知与离线实例、冷暖启动、实时进度、后处理、取消任务和 API 队列；`tests/timing_estimates.py` 验证真实时间记录、样本隔离与预测来源。模拟测试不消耗 GPU 或图片额度。


## 图片导入与提交后的草稿

`image_imports.py` 统一处理参考图、画布上传和头像上传。pillow-heif 固定为 1.8.1，使用官方 wheel 校验；现有 Pillow 12.3.0 原生处理 AVIF。正常尺寸的静态 JPG/PNG/WebP 保留原始字节，其余图片标准化方向和颜色后存为 JPEG/PNG。透明图片保留 alpha；48MP 图片会适配模型的像素上限，转换后的文件上限为 32 MiB。参考图片来源文件仍限制 16 MiB，头像来源文件仍限制 5 MiB，头像最终为 256px WebP。CPU 解码在工作线程运行，并串行限制重型解码，避免阻塞网页事件循环。GPU 实例仅收到原本已支持的 JPEG/PNG/WebP，无需安装 HEIC 解码器。

创作框收到有效任务 ID 后清空本次已提交的提示词、参考图与父版本关联，保留比例、分辨率、时长等参数。提交失败或未收到确认时保留草稿；如果等待返回时用户已开始下一条内容，也不会清空新草稿。作品详情及画布节点中的原始内容不清除。

验证：`tests/image_formats.py` 使用真实二进制 HEIF/AVIF 等文件，覆盖 HEIF 非零主图、EXIF、透明背景、TIFF16、动画首帧、48MP 缩小、容量记录、损坏文件、头像和现有 GPU 解码兼容；`node tests/composer_submission.mjs` 覆盖提交成功、失败、未确认响应、并发新编辑与历史任务重做。

## 模型开放控制

`model_policy.py` 持久保存四个模型的开放标志与修订号，管理接口为 `PATCH /api/settings/models`，仅管理员可调用；所有用户从 `/api/state` 获取有效策略。首次迁移沿用旧图片生成开关状态，不清除任务；旧图片设置接口作为兼容入口仍可批量切换两个图片模型，新界面仅使用独立模型开关。`tests/model_policy.py` 覆盖权限、版本冲突、持久化、暂停/恢复接单、运行中任务续传及画布提交。
