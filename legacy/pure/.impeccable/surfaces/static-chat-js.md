# Chat and canvas writing
Mode: Operate. Local feature extension in the existing Fumiao workbench, not a new visual world.

Authority: existing white/grey Jimeng workbench, coloured logo and system Chinese typography. Narrow conversation history, one readable message column, a bottom composer with model and star credit price. The user's refinement requires the chat model menu to match the existing generation-menu family and canvas AI writing to update the source text node after newly requested replies complete. The latest user refinement places a minimal text composer below the selected node, using the image/video composer geometry, with no right sidebar, history/message area or replace/new-node actions. Personal content remains owner-only; team conversations can be viewed and continued by team members. Completed replies retain their accepted price (1 point by default); stop/failure refunds; canvas automatic writeback and standalone-chat explicit adoption are free. Context and canvas revision safeguards preserve manual edits.

Required checks: desktop, mobile 390px, node-attached canvas text composer, dark appearance; streaming/stop/retry, history/rename/delete undo, safe Markdown, model availability, workspace scopes, existing canvas conflict/undo flow. No new raster assets. Shipping screenshot evidence is a UI capture, not generated art. Finish review and scoped documentation are required.

## Implemented scope · updated 2026-11-07

This is a local extension of the incumbent workbench. The initial layout direction remains in the first-body `CHAT DIRECTION` comment in `static/index.html`; the user's model-menu and direct-writing refinement governs the changed behavior below. Source authority is `canvas/src/chat/ModelSelect.tsx`, `ChatWorkspace.tsx` and `chat.css`, navigation/admin additions in `static/studio.js`, and the inline text-node composer in `canvas/src/main.tsx`. `chat_api.py` persists the writeback context flag and `chat_runtime.py` uses it for the canvas-editing instruction. Compiled `static/chat.js`, `chat.css`, `canvas.js` and `canvas.css` are delivery artifacts, not separate design systems. No unrelated global guidance was refreshed.

- **Entry and reading:** the workbench sidebar offers “对话”. Desktop uses a 210px history column (180px at 1050px and below), a 752px maximum message container and a bottom composer with a 780px maximum container. Replies use 15px/1.85 system text; compact/mobile replies use 14px. User bubbles are right aligned, while assistant Markdown stays in the reading column. Code and tables scroll within their own blocks. HTML is sanitized; model-supplied images and executable markup are not rendered.
- **Conversation controls:** create, resume, rename, copy, delete with undo, and retry the last failed/stopped/interrupted reply. Deletion is available only to the creator or administrator and is disabled while a reply is running. Drafts and the active conversation are scoped to the user, workspace and, in the canvas, project/node. Sending stays disabled while an existing conversation is loading or its selected ID has no loaded snapshot, preventing a restored draft from being submitted into an unintended new conversation. A disconnected browser reconnects to the server-owned reply; scrolling away from the bottom exposes a latest-reply action rather than forcibly moving the reader.
- **Models and price:** DeepSeek Flash is the initial model, with GPT-4.1 also supported. The actual model list follows workspace policy and configured providers. The composer uses a custom model menu matching the generation-menu family, with a box/name/chevron trigger, rounded floating list, grey current row and right-side check. The existing solid four-point star plus numeric price stays beside the send action. The price is per completed reply, defaulting to 1 point per model; administrators can change each model's price. Sending reserves the current workspace's points and locks the accepted price. Completion spends them; stop/failure/interruption refunds them. Canvas automatic writeback and standalone-chat explicit adoption incur no extra charge. Unpriced models or insufficient balance disable sending.
- **Workspace truth:** personal conversations remain owner-only. Authorized team-space participants can view and continue the same conversation. Concurrent conversation revisions are checked before sending, and a conflict reloads the current conversation before the user sends again. This scope follows the existing personal/team workspace boundary; it does not introduce cross-workspace sharing.
- **Canvas writing:** selecting a text node shows a prompt, model menu, numeric star price and generate/stop control below that node. `ChatWorkspace` returns its inline branch before the standalone history, header and message markup, so no right sidebar, conversation history, answer area, replace-text or new-node controls appear. The request includes current node text after pending canvas edits are saved and resumes that node's associated conversation. Newly requested complete replies update the original node; later requests use its current text. Only pending reply IDs persisted by the initiating tab for this user/workspace/project/node are eligible, so reopening does not sweep old replies into the node. Selected nodes and nodes with accepted generation/writeback work remain mounted; changing selection hides the earlier composer without losing its accepted result. Multiple applications serialize through the canvas revision queue. Replacement compares the request baseline with current text, checks again after pending saves and supplies current revision/text to the server. Manual edits are preserved with “节点文字已被修改，未覆盖。请基于当前文字重新生成。”; there is no manual-adoption fallback in this composer. Applications use the existing undo flow. Standalone-chat “放入画布” remains an explicit action adding a text node to an existing or new canvas in the current workspace. Partial, stopped, failed and interrupted replies are never written into the canvas.
- **Admin surfaces:** “模型管理” includes an “AI 对话” group with global/team controls; “生成定价” includes one completed-reply row per chat model. “对话服务” offers DeepSeek/OpenAI credential replacement and connection tests. Saved values are never returned to the form. “已配置”, successful connection testing and a successful generated reply are different states; the UI and acceptance record must not conflate them.

## History-menu and first-exchange title refinement · 2026-11-07

The [scoped direction](../../work/chat-history-20261107/surface.md) extends the existing history controls. Source authority is `canvas/src/chat/ConversationList.tsx`, `ChatWorkspace.tsx`, `chat.css` and `chat_runtime.py`. The existing columns and model menu remain the design authority; the later node-composer refinement below supersedes the former canvas-writing layout. Neither refinement introduces a new visual world or raster assets.

- **Row menu and focus:** right-click a history row, use Shift+F10/ContextMenu on its conversation button, to open its context menu. Opening a menu does not select that conversation. No ellipsis or extra row action button is rendered. The fixed-position menu is 180px wide, capped at the viewport minus 16px, and clamped to an 8px margin on all sides. It reuses the model menu's 14px corners, 6px padding and `0 14px 45px rgba(0,0,0,.13)` shadow. Actions have 40px minimum height, 9px corners, 14px text, 16px line icons and 9px icon/text gaps. The selected conversation retains its selected background while a different menu target uses the hover background. Opening focuses the first enabled action; arrows wrap, Home/End move to the first/last enabled action, and Escape/Tab close the menu and restore its opener. Outside pointer presses, focus leaving, scrolling and resizing dismiss it. The shared 140ms entrance animation is disabled for reduced motion.
- **Rename, deletion and recovery:** rename replaces the target row with a focused, selected input plus save/cancel actions, keeping the current reading snapshot when another row is edited. Enter saves and Escape cancels; submissions disable repeat actions and readable errors stay in the history area. Deletion is soft and retains the existing undo action. The delete action is absent without permission and disabled for a target with an active reply. Deleting another conversation leaves the active conversation intact; undo restores the deleted row without forcing a switch away from another open conversation.
- **First-exchange titles:** a new conversation initially uses its first user message as a provisional title. Only a complete, successful answer to that first user message triggers a best-effort title request with the same `turn.model`; subsequent exchanges do not retitle it and old history is not swept. The request contains the question and answer, each bounded to 4,000 characters, with at most 64 output tokens and an overall 15-second title timeout. Valid text is normalized and capped at 40 characters. The reply is already settled before naming, so naming adds no points and failure retains the provisional title without changing the delivered answer or its charge. A pre-request `custom_title` check and a conditional update requiring `custom_title=0`, no deletion and the unchanged previous title protect manual names from late responses. The list and header use the resulting conversation title.

The [detector result](../../work/chat-history-20261107/design-findings.json) is empty; this is scoped design evidence, not a new full application or accessibility audit. The Linux [server check](../../work/chat-history-20261107/server-check.log) records passing `chat_titles`, `chat_integration` and `chat_transport`; the implementation task also reports a passing production build. Title tests use mocked transport to inspect the request payload, failure/race behavior and five-reply charge accounting. The UI interactions and captures use a local simulated provider. ## Responsive, theme and focus contract

- The chat root is positioned relative, containing its mobile history drawer inside the chat bounds rather than underneath the workbench rail. At 760px and below, history is hidden until opened; its drawer leaves 36px on the right. The inline canvas composer has no history drawer. Background message controls become inert while the drawer is open; the close button, selecting a conversation and Escape dismiss it.
- The text composer shares the image/video `node-composer`: 520px width, 16px corners, 16px 14px 12px padding and canvas surface/shadow. It is anchored below the selected text node and follows canvas pan/zoom/resize. Its measured height feeds both node reveal and placement, reserving 80px for the viewport dock. At 760px and below it uses the existing 12px side gutters, 68px bottom offset, 46dvh maximum height, 12px 10px padding and 14px corners. The generate/stop button is 36px on desktop and 32px on mobile; model, price and process state use 12px text.
- Chat color aliases inherit existing workbench or canvas theme tokens. The standalone 16px-radius composer uses a soft separation shadow (`0 2px 12px rgba(0,0,0,.035)`) and a 2px theme `:focus-within` ring with 2px offset in both themes. The inline text composer follows the existing canvas generator focus treatment; its model and generate controls retain 2px keyboard focus outlines.
- The model trigger uses a 15px box icon, 13px standalone label (12px in the text-node composer), 14px chevron, 6px gaps, 34px minimum height and 10px corners. Its menu opens 8px above the trigger with 14px corners, 6px padding and an offset shadow (`0 14px 45px rgba(0,0,0,.13)`). Options have 40px minimum height, 9px corners and 14px text; the current option uses the theme's grey selected background and a 17px check. Menu width is at least 220px and capped at `min(300px, calc(100vw - 80px))`. Opening focuses the current item; arrows wrap through options, Home/End move to the first/last option, and selection or Escape returns focus to the trigger. Outside pointer presses and focus leaving the component dismiss it. The 140ms entrance animation is disabled for reduced motion. The same model-menu component serves standalone chat and the inline text composer; it is not a native select.
- Credential fields use the workbench field/text colors, 40px minimum height, 9px × 12px padding, 8px corners and a 2px focus ring. Configuration status and placeholder text use the secondary foreground. At phone widths the credential field takes a full row before the save/test actions. No new decorative panels or illustrations were introduced.
