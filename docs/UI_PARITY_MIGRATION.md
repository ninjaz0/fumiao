# 保持原版 UI 的技术栈迁移

目标是同时完成新技术栈、插件化和原版 UI/交互一致性。官网首页、登录/注册、已登录工作台、画布列表与编辑器默认由 React / TypeScript 渲染。工作台内含创作、任务队列、资产库、对话和设置。原协议 NestJS 提供默认业务 API，Python 兼容服务可显式选择。当前入口与运行配置见 [原协议工作台验收](ORIGINAL_NEST_STUDIO.md)。

任务计时新增 TypeScript/PostgreSQL 实现与插件 `1.2.0` 可选能力，已完成原算法、模型特征、执行状态和历史迁移对照。原多实例排队、提交估时与状态 HTTP 已由显式启用的 Nest 提供；详细边界见 [任务计时迁移](TIMING_MIGRATION.md)。

## 已落地

- 原站 HTML、CSS、JS 和图标作为不可变基线。访客画布列表、接口探测失败和显式回退使用固定原文件及资源指纹。
- `/studio` 在原会话接口明确返回 401 时由 Next 内部重写到 React 登录/注册入口；地址栏仍为 `/studio`，不加载旧工作台脚本。有效会话进入 React 工作台。判断使用轻量的工作区接口，不额外读取完整任务/素材列表；接口不可用时保留原加载和错误界面。
- 官网首页 `/` 由 Next App Router、React 服务端组件和 TypeScript 交互组件实现，不再加载旧 `home.js` / `theme.js`。沿用原 CSS、图标指纹、DOM 结构、文案及 SVG 图形；没有引入开发版工作台样式。
- 首页的主题与滚动由 React 管理；页面绘制前恢复外观并转发旧登录/邀请 hash 链接。Next 脚本使用每个响应独立的 CSP nonce，生产环境不开放 `unsafe-inline` / `unsafe-eval` 脚本权限。实现依据：[Next.js 官方 CSP 文档](https://nextjs.org/docs/app/guides/content-security-policy)。
- 网关保留原 HTTP 方法、路径、查询、工作区头、Cookie、原错误体和状态码；上传及 SSE 不整体缓冲，Range、下载和重定向保持可用。写请求失败不自动重试。
- 会话和业务数据仍由一套原版数据库负责；没有把新旧身份、工作区或积分混合写入。
- 网关会剥离客户端提供的代理身份头，避免伪造来源；公网部署前需明确可信反向代理及登录限流策略。当前仅限本机预览。
- 原版 API 清单来自固定源码的 AST，120 个 method/path 对记录在 `baseline/contracts/routes.json`；可用 `python3 scripts/list-original-routes.py --check` 检查漂移。

## 后续兼容顺序

首页、登录和注册、工作台、已登录的画布列表及画布编辑器沿用原 DOM 结构、CSS、图标、文案与事件行为。后续业务后端继续按有关联的数据和契约成组验收。

| 契约组 | 必须保留的行为 | 目标实现 / 当前状态 |
|---|---|---|
| 鉴权、资料、工作区、状态聚合 | `fm_session`、默认空间、数字编号、个人空间隐私、成员撤销立即生效、原错误体 | 同一隔离 Next + Nest + PostgreSQL 实例已验证身份、状态聚合、团队、邀请码和成员删除。默认工作台使用原协议 Nest |
| 素材、收藏、素材包 | 旧媒体编号、引用保护、容量、头像、批量下载、Range、跨空间拒绝 | Nest 原协议上传、读取/删除、收藏、批量操作及素材包已隔离验证；画布及分镜活动引用由原协议后端保护 |
| 画布与镜头 | 原完整文档结构、自动保存、修订冲突、撤销/重做、分镜/旁白/导出、历史回填 | 已登录列表和默认编辑器由 React 渲染，默认业务使用原协议 Nest |
| 生成、价格、积分、队列 | 模型规格、冻结/退款、幂等、取消、未知提交状态、模型访问控制 | NestJS、BullMQ 和版本化插件提供原估时、生成、积分、取消及状态接口 |
| 对话 | 流式快照、停止/恢复、历史菜单、自动命名、画布文本写回保护 | 已支持完整原会话历史导入。工作台和画布对话已接入原协议 HTTP/SSE，隔离验收覆盖 PostgreSQL / BullMQ 执行、积分及写入画布 |
| Muse / Flow / GPU | 由插件完成鉴权、健康检查、提交、轮询/取消、下载/回传；原页面配置和状态语义保持 | 普通配对与请求型提供方继续运行；贡献资源池及专用验证接口退役 |
| 支付与管理 | 原设置页、邀请、成员、权限、支付回调核实、一次到账 | Nest 提供原管理与充值接口；实际支付接入待验证 |

有关联的数据写入必须一起迁移，不能先将画布 CRUD 指向 PostgreSQL、而让生成回填仍修改 SQLite。每组切换前要覆盖旧请求/响应、权限、并发和失败恢复，必要时使用隔离的完整数据迁移实例验证；未通过时继续保留原版完整链路。

## 完成标准

1. 常规网站路径完全由目标技术栈处理，页面逻辑完成 React / TypeScript 迁移，业务接口完成 NestJS / PostgreSQL / Redis + BullMQ 迁移；移除对原版 Python 业务服务的运行依赖，保留归档仅用于参考和迁移。
2. Muse、Flow、GPU 与新模型提供方均由版本化插件接入，核心应用不承担提供方特有逻辑。
3. 所有原页面的视觉结构、文案、布局、交互和已有功能得到保留；语言或构建方式变化不能成为界面差异的理由。
4. 原请求契约、账户/空间隔离、任务幂等、积分结算、文档冲突和流式协议通过回归验证。
5. 数据迁移、恢复点、实际提供方接入和容量验证完成后，才讨论上线切换。当前没有修改 nvmes.com。

`pnpm test:studio:nest --routes` 可复跑全部 120 项方法和路径归属、私有存储与 BullMQ 端到端运行检查。完整界面一致性和默认应用切换的验收独立进行。[原协议 Nest 工作台验收](ORIGINAL_NEST_STUDIO.md)

## 原素材、头像读取与素材库操作（已隔离验证，尚未切换）

Nest 原协议支持 `/media/{key}`、内置/上传头像读取及参考素材删除。内部 UUID 外键与外部 32 位媒体编号分离，迁移保留原文件、URL、修改时间、任务输入/输出、素材包及画布引用（包括仍在画布中的历史任务结果）。私有 S3 下载只在权限校验后生成临时地址；头像经过登录及有效资料引用检查后流式返回。更换为内置头像时，仅在最后一个用户引用消失后移除文件。

收藏与批量删除使用同一份 UUID 外键关系，原协议仍返回 `job:数字编号` / `asset:32位编号`；Advanced 接口读取和修改同一份收藏。生成结果按任务归一，导入保留收藏顺序及用户隔离。批量删除整批校验权限、终态及外部引用后提交：任务保留内部删除标记，账本与幂等编号不变，释放素材引用、文件和容量；两种协议都不再列出已删除任务。

打包下载票据只保存哈希、归属和 15 分钟有效期；读取时重新校验每个素材的访问权限。文件在发送响应头前打开，使用 ZIP_STORED/Zip64 流式打包，保留原条目顺序、文件名、权限和字节；文件缺失及客户端断开会关闭全部已打开对象。未把整个压缩包装入内存，也未绕过私有存储签名权限。

`pnpm test:media` 使用临时原服务、合成数据导出及隔离 PostgreSQL/PGlite，逐值比较 175 项契约：字节、ETag、Last-Modified、Range/多段 Range、下载名、JSON 响应头、工作区权限、收藏、批量删除、完整 ZIP 字节，以及后续新增的任务撤回与单条删除。报告位于 `.runtime-advanced/media-parity/report.json`。平台测试另覆盖签名地址授权、任务/文档引用保护、并发保存与删除、容量回收、删除后重试不重复扣费、账本保留、源文件长度变化及客户端断开后停止读取。

这一步不代表完整素材链路迁完。图片/头像上传已接入独立 Node 工作线程和私有存储，取帧来源、上传限制、权限、响应与格式输出已纳入对照。全局容量计数与生成任务预留由 PostgreSQL 事务统一处理。116 项图片对照和素材包原协议已通过隔离验证，活动分镜引用保护仍待完成；默认 `/studio` 后端保持原完整链路，工作台与画布也仍待 React / TypeScript 迁移。

## 积分历史与管理契约（已隔离验证，尚未切换）

## 上传转换与全局容量（已隔离验证，尚未切换）

`POST /api/assets` 与 `PUT /api/me/avatar` 在独立 Nest 原协议应用中接收原始请求体。保留 16 MiB / 5 MiB 上传限制、工作区优先级、取帧来源权限、原错误文本、头像资料更新以及旧头像最后引用清理。源文件只写入临时目录，转换通过有并发/队列上限的工作线程处理；超时、排队取消与正在运行的取消均释放工作槽和暂存文件。没有通过 Python 服务完成这些新接口。

`asset_provenance` 保存原取帧来源公开编号、内部 UUID 与时间；导入同样恢复此关系，源媒体删除后仍保留来源编号。私有存储写入或数据库提交失败会清理此次上传对象。

`storage_capacity` 与 `storage_holds` 在 PostgreSQL 中统一核算素材字节和预留。生成任务预留 64 MiB（文字对话不预留媒体空间），产物入库抵扣剩余预留，终态释放余额；重试不重复占用。256 MiB 分镜预留的数据结构已建立，但原分镜接口尚未接入。全局计数在事务提交时按净变化一次更新，只有最终状态可提交；同一工作区的既有容量限制继续有效。`FUMIAO_QUOTA` 显式设置共享数据库上限，未设置时保留已存值。磁盘模式另检查对象目录可用空间。

`pnpm test:canvas-validation` 用隔离的真实原 SQLite 数据执行原校验器，对照 6,247 个场景及 55 个模板选型。TypeScript 一侧使用公开资源快照适配器，验证规则与授权调用边界；它尚不是原画布 PostgreSQL 保存事务的集成验收。`pnpm test` 另验证 PostgreSQL 下显式启用、降级、版本不可变、外部插件注册、错误注册回滚，以及图结构和引用检查。

原文档存储、历史导入、生成及基本操作 HTTP 的进展见后续各节。通用画布 JSONB 投影不能作为完整原文档存储；尤其不得重写正文中的素材 URL 或丢弃 NUL 字符。默认 `/studio` 仍通过 Python 兼容后端运行。

## 原画布存储与基本操作（隔离验证）

迁移 `021_original_canvas.sql` 增加原画布权威记录：标题和文档使用 UTF-8 `bytea`，保留 NUL、原素材 URL、节点字段和原公开编号。父文档只保留内部标记、归属和修订号；原型列表不读取这些记录，原型保存/删除接口也不能覆盖它们。此前导入的通用 JSONB 投影保持原样，不能据此恢复已改写的原文；原画布内部服务读取这类尚未迁移的文档会拒绝操作，完整原历史导入的后续实现见下一节。

`OriginalCanvases` 已实现新原画布的列表、创建、读取、修订保存、复制和删除。模板文字/布局、显式标题、空白裁剪、最多四张封面、当前/最新成品选择、个人/团队权限、75 字符副本标题与旁白复制均按原逻辑处理。源站的 `get/save/duplicate/delete` 按画布所属工作区授权，不受当前选中工作区影响；列表/创建才使用选中工作区。对话上下文优先读取新原文档，旧导入的临时回退仍保留，未将写回接口混接。

节点、媒体引用、任务链接和批次关系独立保存。明确引用与素材包保护和保存事务一起更新；刚完成的关联任务产物通过当前节点和任务链接动态保护，移除节点后释放这类保护。重复角色产生同一节点/媒体主键冲突时，整次保存回滚，保留原行为。个人空间始终不继承管理员访问权限。

保存先锁父记录，再读取原文档，避免等待并发保存时读取旧的关联行；修订冲突保留原提示。每个工作区的创建锁防止并发超过 200 个画布。失败回滚同时保护标题、原文档、修订和引用；复制只引用已有产物/旁白，不提交提供方任务、不扣费。

`pnpm test:canvas-storage` 用真实原 FastAPI/SQLite 生成 61 个操作结果及完整项目/引用/链接快照，在隔离 PostgreSQL 和 PGlite 对照通过。另有 5,041 组原旁白集合顺序对照，确保复制产生的链接顺序一致。平台测试验证 UTF-8、原型写入隔离、对话上下文、引用保护、晚完成产物、事务失败和并发容量；真实 PostgreSQL 还验证复制实际等待行锁后读取最新文档。HTTP 接入及差分见下文。

后续章节记录完整画布历史导入、生成与运行记录服务和基本操作 HTTP。删除含活动分镜导出的画布时，原合成取消语义须随导出模块一起实现。


## 原画布完整历史导入（隔离验证）

导出新增 `canvasVersion: 1`，覆盖 `canvas_projects`、`canvas_media_refs`、`canvas_job_links`、`canvas_run_batches`、`storyboard_exports` 和 `storyboard_export_refs`。CLI 要求完整版本；缺表、活动合成和未结算任务会拒绝导出。合成顺序保留原 SQLite `rowid`。旧导出和已改写正文的通用 JSONB 投影不能用于完整恢复，须从静止的原实例重新导出到空的隔离目标库。

导入不再重写画布里的素材编号、URL 或正文，也不转换为原型 React Flow 数据。原标题、文档、任务输入、批次结果、合成快照、字幕和错误采用 UTF-8 `bytea` 保存；原始六表另存入按工作区归属的 `legacy_canvas_records`。原文保留 NUL、Unicode 和 JSON 格式，节点索引只用于关系查询。保存后仍采用原修订检查与插件规则。

导入前检查归属、引用工作区、唯一标识、候选子请求 UUID、任务链接和已结算费用。节点已移除、任务已删除造成的空链接和批次中的旧任务编号仍保留；不把历史缺失对象伪造成新任务。曾退出团队的创建者可以保留历史所有权，导入不恢复其当前访问权限。完成的合成保留已删除画布的空关联及历史快照，不将快照重新建立成活动引用。

迁移 `022_original_canvas_import.sql` 增加合成历史和原始归档。全部账号、工作区、原文、关系、合成与账本在同一 SQL 事务恢复，链接及合成顺序的序列推进至原上限之后。任务公开编号还计入费用/账本中已删除任务的上限，防止新任务占用旧批次引用的编号。相同来源和指纹重复导入不覆盖后续写入；内容变化拒绝导入。对象复制仍先于 SQL，失败后可能留有确定键名的未引用对象，可供重试复用；没有增量导入或双写。历史导入不创建执行消息、不冻结或再次扣除费用、不启用提供方凭据。

`pnpm test:canvas-import` 从真实原 FastAPI 创建候选批次、普通生成、旁白和合成请求；用本地合成完成结果触发原积分结算，整个流程不调用真实提供方、不执行成片编码。六表原始字段与新关系表逐字段比较，再对照 36 个读取、列表、复制、保存冲突、跨空间访问、删除、历史运行与请求重试操作及全部六表快照。另验证活动导出和两类缺表拒绝。平台测试覆盖原文归档、空任务链接、创建者退出团队、27 类不合法历史、SQL 晚失败整笔回滚、并发重试和不覆盖新写入。

删除画布时，已完成合成保留并解除画布关联，失败合成随画布移除；活动合成媒体引用已有删除保护。活动合成的取消、执行与恢复仍须随导出模块实现。本节仅完成历史存储和导入，生成/候选/旁白提交、运行列表/导出服务、对话采用、HTTP/SSE 与 React 工作台/画布仍未全部完成。默认原 UI、兼容后端和固定生产基线保持不变，不能把该单元通过视为整站切换完成。


## 原画布生成与运行记录（隔离验证）

`OriginalCanvasRuns` 支持单次生成、1/2 个候选、旁白和运行列表。单次/旁白/候选保留各自原 UUID 命名空间及重试顺序：已受理请求先返回旧结果，再考虑新修订或价格；节点、画布或候选数量不匹配时保留原冲突说明。删除任务后的普通链接重试拒绝，已记录的完整候选批次仍返回旧结果，不重建任务。运行列表保持链接倒序、输入快照、候选索引、GPU 节点与画布节点的区别，使用全局队列估时；运行列表保留任务说明，不套用工作台的“等待模型开放”显示覆盖。

生成通过 `OriginalGeneration.submitOn` 复用原提供方适配器和计费/准入事务。工作区取画布归属；源文本按原 Unicode 空白规则拼接，参考图保留连线顺序和去重语义，素材包在提交时检查版本并冻结。候选第二条失败、链接插入失败都会回滚任务、账本、冻结、事件和发件箱。父画布行锁及用户请求锁串行化并发保存/提交、同 UID 重试和跨画布冲突；任务及执行配置仍按已接受的插件版本冻结。

Muse `1.12.0`、Flow `1.11.0`、GPU / 图片 `1.10.0` 增加 `canvasSubmission` version 1 纯数据能力。默认图片/视频/旁白模型、H3 输入、固定采样和模型标签由所属插件声明，核心不按提供方名称选择。旧版本保持不变，安装不自动升级目录和连接；能力缺失时拒绝半迁移生成。

`pnpm test:canvas-runs` 在真实原 FastAPI/SQLite 与隔离 PostgreSQL/PGlite 对照 95 个场景，比较响应以及任务冻结字段、链接输入、候选记录和钱包状态。覆盖 H3 两种模式、Muse 固定步数、Flow、默认图片、素材包、旁白、模型禁用时的运行说明、错误顺序、余额不足整批回滚和团队权限。PostgreSQL 回滚可能留下编号空缺，比较按成功创建顺序映射新任务/链接/画布编号；已有历史公开编号在 `test:canvas-import` 中逐字比较。新任务的墙钟时间只检查整数契约，随机旁白种子检查范围，其他运行字段与估时结果直接比较。导入对照已扩充为 36 个操作，包含历史运行列表及普通/候选/旁白重复请求，未调用真实提供方。

平台测试另验证并发同 UID、同节点竞争、跨画布 UID 冲突、第二条费用失败和数据库晚失败、空链接重试及插件未启用时的拒绝。任务文本使用迁移 `023` 和新版提供方适配器保留 NUL 与原版 Unicode 裁剪，详见 [无损任务文本](LOSSLESS_GENERATION_TEXT.md)。

## 原画布 REST 与运行 HTTP（显式启用）

`API_PROTOCOL=original` 的 NestJS 应用通过 `OriginalCanvases` 和 `OriginalCanvasRuns` 提供以下 PostgreSQL 路由：

| 方法 | 路径 | 操作 |
| --- | --- | --- |
| GET | `/api/canvases` | 列出选中工作区的画布和模板 |
| POST | `/api/canvases` | 创建画布 |
| GET | `/api/canvases/{pid}` | 读取画布 |
| PUT | `/api/canvases/{pid}/document` | 按修订号保存 |
| POST | `/api/canvases/{pid}/duplicate` | 复制画布 |
| DELETE | `/api/canvases/{pid}` | 删除画布 |
| GET | `/api/canvases/{pid}/runs` | 按链接编号倒序列出画布任务、输入快照、候选归属和估时 |
| POST | `/api/canvases/{pid}/nodes/{nid}/runs` | 提交图片或视频任务 |
| POST | `/api/canvases/{pid}/nodes/{nid}/candidates` | 原子提交一个或两个候选，返回任务编号与总积分 |
| POST | `/api/canvases/{pid}/nodes/{nid}/narration` | 提交视频节点旁白 |
| GET | `/api/canvases/{pid}/exports` | 列出最近 20 条成片记录 |
| POST | `/api/canvases/{pid}/exports` | 按画布修订和 UID 提交成片 |
| GET | `/api/storyboard-exports/{key}/subtitles` | 下载 SRT 或读取 VTT |
| POST | `/api/canvases/{pid}/shots/download` | 为有序镜头 ZIP 创建私有下载票据 |

来源检查先于请求体校验。创建和保存的 JSON 解码与字段校验先于登录检查；登录后才检查空白名称、工作区或画布权限、修订号及图和素材引用。复制和删除忽略请求体。保存遇到同一修订号的并发请求时，只有一个请求提交，另一个返回原版 409。重复媒体引用的数据库约束错误保留原版纯文本 500 与事务回滚。

三个生成操作复用原生成服务和版本化提供方插件。请求先校验来源和请求体，再认证会话和检查画布权限。通过权限检查后，幂等重试优先于修订号、忙碌状态和价格检查。任务和费用归属画布工作区。候选批次中的任务、画布链接、积分冻结和 outbox 同时提交。新的运行请求保留超出 JavaScript 安全整数范围的 JSON 整数，运行列表也原样输出链接编号及输入快照中的大整数。

`023_lossless_job_json.sql` 和既有无损文本插件版本一起用于此 HTTP 切片。GPU `1.11.0`、Muse `1.13.0`、Flow `1.12.0` 和图片 `1.12.0` 仍由管理员显式激活并选择匹配的连接版本。

`pnpm test:canvas-rest` 并行启动固定版 Python/SQLite 和 opt-in NestJS HTTP 服务，比较请求顺序、权限、错误、响应结构和并发。测试用本地模拟提供方配置和隔离钱包验证幂等、候选整批回滚、积分冻结与结算，并检查大整数在原始响应中的数字写法。设置 `STUDIO_PYTHON` 指定安装了固定依赖的 Python，设置 `TEST_DATABASE_URL` 在测试用 PostgreSQL 库中创建独立 schema。测试映射运行时分配的公开编号，另行检查时间戳、随机旁白种子和列表顺序。

成片和镜头下载沿用相同的请求校验与画布权限，并分别复用 PostgreSQL/BullMQ 成片队列和私有 ZIP 下载票据。使用 `pnpm test:canvas-rest --storyboard` 运行带 Redis 的原版 HTTP 对照，详见 [原版成片导出](STORYBOARD_EXPORTS.md)。

默认 `/studio` 经过 Next.js 和原协议 Nest。`/canvas/:id` 默认运行 React / TypeScript 画布编辑器。验收比较原有 58 个浏览器状态及跨空间无权限、后端中断两态，要求 UI DOM 一致和零像素差异。已通过 Next → 显式启用的 Nest 原协议 → PostgreSQL/BullMQ 的历史导入、自动保存、私有素材、生成、导出、对话 SSE、权限和结算端到端测试。范围见 [画布编辑器一致性](CANVAS_EDITOR_PARITY.md)。
