# 插件接入与零模型启动设计

供 Fumiao Advanced 原开发 agent 实施。设计依据为 2026-11-18 集成分支 `t3/integrate-studio-stack` 的提交 `7c57754f71e4161a0d880369e7403eca92e22ea3`。下面给出产品决策、拟议契约和验收条件；文中的新接口和数据结构均待实现。

**产品范围更新：取消 fumiao-worker（代码名 fmWorker）及贡献积分。** 新系统移除贡献客户端、共享算力资源池、贡献用量上报、收益账户与奖励发放，包括专供贡献节点使用的 Flow 验证流程。这些功能从发行清单、插件市场、SDK 和上线验收中退场。本地实例插件仍支持配对机器执行生成；BullMQ 继续调度后台任务；用户充值、生成消费、积分冻结、结算与退款沿用现有账本。

## 1. 用户实际看到什么

新装系统登录普通 `/studio` 后，设置里有「插件」入口，模型目录为空，没有「GPU 实例」「GPU 接入」或「实例接入」。用户仍能管理工作区、浏览素材、编辑和保存画布。进入创作页时可以写提示词、保留草稿，模型选择器显示空态，生成按钮不可提交。管理员可从空态进入插件页，成员看到联系管理员的提示。模型管理与定价可以显示空列表。

管理员安装「本地实例接入」成功后，原设置中 GPU 标签所在位置出现「实例接入」。点击进入原配对、命令复制、节点状态和管理流程，按原成员和管理员权限展示。此时系统已经认识这个插件声明的模型，即使还没接入任何机器也能在插件详情查看模型、配置条件及就绪状态。安装不代表已经部署推理环境。

单独安装 Muse2API 或 Flow2API，系统只新增对应插件的模型和连接设置。配置服务地址和凭据后，管理员沿用现有模型权限与定价规则开放生成。两者均可在没有本地实例插件的系统上运行。安装三者后，用户从同一个模型选择器使用获准的模型。

| 安装组合 | 设置入口 | 目录与提交 |
|---|---|---|
| 空 | 插件 | 0 个模型，无估价或生成写入 |
| 仅本地实例接入 | 插件、实例接入 | 识别该版本声明的本地模型；能否提交或等待节点，遵守该模型原准入规则 |
| 仅 Muse2API | 插件，详情内配置 Muse2API | 识别 Muse 图像、视频；连接未配置时给出原因 |
| 仅 Flow2API | 插件，详情内配置 Flow2API | 识别 Flow 目录；保留原隐藏模型、引用与续写规则 |
| 多个官方插件或第三方插件 | 各自贡献的入口按权限出现一次 | 合并可见模型，新请求锁定明确的提供方、版本及连接 |

本次明确改变的 UI 是插件入口、按安装情况出现的设置项、「实例接入」名称、缺少模型时的空态，以及移除贡献客户端、资源与收益相关入口。其余页面沿用原 DOM、CSS、图标、文案和交互。建议将插件管理限定为站点管理员操作，成员可以只读查看对当前空间公开的插件和模型。安装范围按部署实例管理，模型与连接的使用权限继续按工作区管理。

## 2. 现状及可复用的实现

以下路径相对于上述提交。实施前请在已经整合默认 React、Nest、容器和存储的候选分支核验，不要从主目录的较早快照重新实现这些功能。

| 接入方式 | 目前的真实链路 | 插件要接管的边界 |
|---|---|---|
| 本地 GPU | `apps/web/studio/SettingsGpu.tsx`、`packages/original-api/src/nodes.ts` 实现选模型、发配对码、复制安装命令、登记和撤销。原客户端走 `/api/pairs`、`/connect/:file`、`/agent/enroll`、心跳、领取、取私有输入和回传。Advanced worker 另走 `/agent/v2/*`。 | 复用 `plugins/gpu/src/paired-agent.ts` 的设备预算、通道、资格和成片校验。菜单、配对、下载、新节点登记、新任务领取均需有对应安装授权。两套协议分别保留原编号、会话和鉴权契约。 |
| Muse2API | 归档在 `legacy/pure/muse_provider.py` 和 `legacy/pure/services/muse2api/`。现有 `plugins/muse/src/lifecycle.ts` 按图像/视频调用 `POST /v1/images/tasks`、`POST /v1/videos`，拿到上游任务号后按号轮询，再下载、校验、保存。 | 保留明确拒绝、延后重试、未知提交、可恢复轮询及结果保存的区别。显示名称可写 Muse2API，插件 ID 继续用 `muse`；保留公开模型 ID 和价格档位。 |
| Flow2API | 归档在 `legacy/pure/flow_provider.py` 和 `legacy/pure/services/flow2api/`。现有 `plugins/flow/` 包含模型目录、上游模型映射和流式适配；向 `POST /v1/chat/completions` 发送请求，从 SSE 读取进度及结果，续写会带来源媒体标识。 | 插件拥有参考素材数量、续写、串行调度、错误映射和回执恢复规则。保留现有断流处理，已拿到成品回执的任务可继续保存，避免再次生成。沿用 ID `flow`。 |

Muse2API、Flow2API 首版安装的是连接已有服务的适配器。管理员提供已部署的服务地址和凭据，插件中心说明所需上游版本和连接条件。安装动作不代为部署上游软件。Flow2API 直接通过已配置的 HTTP 服务生成。贡献节点的验证接口和凭据随旧资源池一起退役。

### 必须拆开的现有耦合

- **安装与分发。** `packages/platform/src/plugins.ts` 的 `PluginRegistry` 列举多个历史适配器。`scripts/migrate.ts` 调用 `installBuiltins`，会把目录写入数据库；`packages/platform/src/importer.ts` 也有安装调用。将“本发行版可提供的包”与“本站已安装的插件”分开。内置适配器可以随镜像分发，启动时只索引可安装包。
- **空目录与就绪判断。** `packages/original-api/src/state.ts` 的 `providers()` 要求贡献字段拼齐固定 schema；连接数大于一也可能使整个状态请求失败。画布规则、图片设置及对话目录也有要求插件齐备的校验。健康检查应区分数据库/存储不可用、已安装插件损坏和用户尚未安装插件。
- **前端默认值。** `apps/web/studio/Settings.tsx`、`settings-tabs.ts` 固定列出 GPU；`studio/state.ts`、`SettingsPrices.tsx`、`CanvasWorkspace.tsx` 含 H3、Muse、Flow 等固定模型或分组。仅隐藏菜单仍会在创建画布节点、恢复草稿、估价或定价时产生幽灵模型。
- **协议绕过入口。** Next 代理、原协议 Nest 控制器、Advanced 的 `/agent/v2` 和 worker 都可独立访问。现有 `pairedAgent()` 从代码表取实现。授权必须检查当前安装和授权版本，不能仅依靠“代码可解析”或“库里有历史版本”。
- **插件之间的代码依赖。** Flow 的产物检查从 Muse 导入媒体检查，Flow 生命周期也复用了 Muse 的 JSON 兼容函数。将这类行为已验证的纯工具移到中立共享包，或作为显式的底层库随包分发。Flow 单装、Muse 卸载或升级时，都不能改变 Flow 的执行版本与结果。
- **管理 API 的会话。** `apps/api/src/main.ts` 已有插件版本、连接、健康检查及升级的管理接口；普通 Studio 走独立的原协议 Nest 应用。新设置页通过原工作台会话和 CSRF 进入同一应用服务，复用底层事务与授权，不拼接两种会话或复用另一协议的用户编号。

## 3. 插件契约与开发者接入

沿用 `packages/plugin-sdk` 的 `Manifest`、`ProviderPlugin` 和 `Receipt`，保留现有 v1 插件、版本锁定、配置 JSON Schema、`models[]`、`request` 和 `pull`。新增版本化的**安装包描述**，由它引用一个或多个不可变适配器版本。这样本地实例包可同时绑定执行模型和配对协议；只提供界面的扩展也无需伪造一个模型来满足 v1 manifest 的非空约束。

建议的包描述示例（拟议格式；示例里的执行版本取自核对提交）：

```json
{
  "packageContract": 1,
  "id": "gpu",
  "version": "1.0.0",
  "label": "本地实例接入",
  "adapters": [
    { "id": "gpu", "version": "1.11.0", "role": "model-provider" }
  ],
  "capabilities": [
    { "type": "paired-agent", "version": 2, "provider": "gpu" }
  ],
  "settings": [
    { "key": "instances", "slot": "settings", "label": "实例接入",
      "view": "paired-agent-panel", "requires": "paired-agent" }
  ]
}
```

1. **包与版本。** `packageContract` 约束包格式，适配器的 `contractVersion` 约束执行协议。发布物列出精确依赖、宿主兼容范围和内容摘要；同 ID、同版本内容不可覆盖。安装器拒绝声明已退役贡献能力（如 `fmworkerResources`）的包，并给出具体原因。首次安装直接激活本次选定版本并注册菜单和目录；升级需预检并显式切换。
2. **模型发现。** 首版以激活版本的 manifest 为权威，安装时校验后立即登记模型、类型、参数、素材约束、显示顺序、价格档位和能力。节点心跳、上游可用性影响运行状态，不创建全站模型，也不抹掉管理员配置。新增型号通过新插件版本发布。第一版无需假设上游有统一的模型枚举 API。
3. **前端扩展。** 插件只在宿主定义的 `settings` 等插槽中贡献命名空间内的菜单项。宿主提供连接表单、模型清单和参数表单等通用视图；受信任的官方能力可绑定复用原 UI 的专用视图，如实例配对或 Flow 选择器。第三方声明引用已支持的控件、字段和权限，不能注入脚本、任意 URL、HTML 或扩大当前用户权限。无专用 UI 的普通模型必须能用通用表单跑通。
4. **外部插件。** 优先开放已有的独立 HTTP 服务契约。服务实现 `GET /health`、`POST /submit`，异步服务另实现 `POST /inspect`；请求携带固定任务号、模型和幂等键，回执可为 pending、completed 或 failed。已有 `plugins/example-remote/` 可作为开发起点。远程插件通过校验后可声明目录和通用 UI；本地纯函数、节点租约、成片验证等特权能力仍由受信任的发行包实现。包安装不能在 API 进程执行用户提交的 npm 包或安装脚本。
5. **开发者交付路径。** 给 SDK 补包描述 JSON Schema、参数控件映射、兼容版本表和可运行模板。开发者基于 echo 示例声明一个新的图像或文本模型、启动回环服务、校验 manifest、由管理员导入、测试连接并启用、从普通 Studio 提交、查看结果，再测试停用与卸载。交付一个离线契约验证命令，检查未知能力、重复 ID、输入 schema、价格匹配、不可变版本及回执格式。以一个未在核心源码出现的插件 ID 完成全过程作为 SDK 的发布条件。

### 插件管理界面

「插件」页沿用现有设置页的列表、表单和确认交互。可安装列表展示名称、来源、版本、贡献的模型及菜单。管理员点击安装前可看到会新增哪些入口、需要哪些连接信息；安装成功后直接进入详情。详情显示已识别模型、连接状态和可用操作：本地实例插件提供「实例接入」，Muse2API 和 Flow2API 提供服务地址、密钥写入、连接测试、模型与定价入口。健康检查只读，不触发生成。成员可见的只读信息须在服务端裁剪。

连接停用、插件停用和卸载的界面应分别说明影响哪批新请求、还有多少在途任务、历史作品如何查看。安装、配置与状态读取失败可独立重试。公开目录的 refresh 以同一安装修订为准；切换工作区或插件被停用后，保留已写提示词和参数，将失效选择标作不可用，等用户主动换模型。

### 从模型声明到实际执行

| 层次 | 规则与返回结果 |
|---|---|
| 已识别 | 激活包通过校验后，管理员立即看到它提供的所有模型、版本、类型和状态。尚未配连接也显示「待配置」。 |
| 用户可见 | 按工作区、全局/团队开关、隐藏策略及原权限投影目录。UI 获取模型引用、标签、可用控件、原因码等公开值。连接密钥、内部对象路径及其他空间信息不进入投影。 |
| 允许提交 | 服务端重新检查当前安装、权限、连接绑定、插件准入策略、价格修订、余额与素材归属。对允许等待节点的 pull 模型沿用原排队语义。没有可执行配置时返回可处理原因，且不冻结积分。 |
| 已受理 | 在同一事务固化插件/适配器版本、模型、连接及凭据快照、价格、引用和幂等请求，创建任务及 outbox。BullMQ 消费按冻结版本执行，现有租约、回执、私有产物和最终结算流程继续生效。 |

同一旧公开模型 ID 继续绑定原提供方。第三方新模型推荐使用发布者前缀，内部用“插件 ID + 模型 ID”标识；对旧接口要求全局唯一的公开 ID 做事务级冲突检查，失败时回报冲突所有者，整包不生效。多个连接提供同一模型时，沿用可唯一确定的现有连接，新增场景使用工作区显式绑定；歧义只阻止该模型提交。停用后打开历史任务或画布，仍显示保存时的模型名称和原参数。重新生成需用户选择当前获准模型，无权静默替换。

**通用表单映射。** 模型种类取自 manifest，输入 schema 的枚举、字符串、数值范围和布尔值分别映射到宿主已有选择器、文本、数值和开关，参考素材取已声明的类型及数量限制。v1 模型缺少 Studio 展示元数据时，回退到 manifest 标签、种类和稳定顺序；缺价时标记待定价并禁止计费提交。已有价格和开关沿用原规则。宿主不支持的必填控件应在安装预检中说明，不能让用户提交缺字段的任务。

### 画布上传图片与视频模型输入

画布上传一次图片，就在当前工作区生成一份私有素材。画布使用图片节点的 `media_id` 和连到目标视频节点的输入边引用它。即使系统尚无模型，也应能上传、连线、保存和重新打开该图。选择任一支持图片输入的视频模型后，可以沿用同一张图生成，切换插件或模型无需重新上传。

- **素材归属和角色。** 图片归工作区。参考图、首帧、尾帧等用途属于本次输入与目标节点之间的关系。同一素材可以在不同镜头承担不同角色。仅支持首帧的模型按首帧接收一张图；需要显式选择角色时保留图片并提示选择。模型只接受文本或超出数量、格式、角色限制时，保留素材与连线，说明原因并阻止无效提交，不能静默丢图或截断。
- **插件契约。** 模型按具体型号和模式声明图片输入角色、数量及其他限制；沿用已有的引用类型和数量 schema，缺少角色表达时增加版本化声明。工作台和画布读取同一份声明。服务端按工作区授权读取素材，在任务受理时冻结有序素材引用与角色；各插件再映射成自己的上游请求。H3 的专用参数仍可描述它的原生模式，普通图片上传、素材存储和通用连线均不依赖 H3 或其他插件。
- **衔接近期修复。** 提交 `94fdafd` 的 `portableReferences()` 已能在从 H3 切到适用目标时，把旧 `h3_refs` 和首尾帧槽位中的图片转换成图片节点与连线。实现还会为新图片节点填入 `muse-image`。开发基线须包含该提交或等价修复；插件化后，纯素材节点可独立保存，无需填入生成模型。沿用已有旧文档转换、节点和连线复用、撤销重做及重开幂等行为；可表达的角色与顺序随输入保留，角色不兼容时由用户确认映射。

普通 Studio 还需要一条通用适配路径。官方模型沿用现有原提交契约和响应；第三方 v1 request 模型通常没有 `originalSubmission`。由新增的原协议 Nest 入口接收当前工作区的模型引用、参数、引用素材、价格修订和幂等 UID，按 manifest 校验，调用共用任务接受事务并返回 Studio 可用的公开任务编号。轮询、资产回填和历史列表沿用同一状态投影。文本/对话只有在声明对应流能力时才提供流式交互；不能把有限的 HTTP 回执接口解释成支持全部原版聊天能力。

## 4. 持久化、接口和运行时

| 数据或接口 | 实施约束 |
|---|---|
| 可安装包目录 | 官方包来自发行清单，第三方包由管理员导入。此目录仅表示可安装；打开插件页不会写入 `studio_catalog` 或创建连接。 |
| 插件安装记录（新增） | 每个部署按包 ID 唯一，保存活动包版本、状态、修订、操作者和时间；不可变包版本记录关联适配器/能力清单与摘要。沿用 `plugin_versions` 保存执行版本，保留旧任务可解析的适配器。 |
| 模型、价格、连接 | 复用 `studio_catalog`、现有分档价格、策略、连接与工作区权限。按活动安装关系投影，保留历史行；同版本重复安装不增修订、不重置管理员价格。出厂包、已安装、已配置、可使用分别可查询。 |
| 菜单和状态读取 | 建议增设原协议 `GET /api/studio/extensions`，返回当前用户/空间可见的菜单、模型能力和修订。`/api/state` 继续提供已有字段的兼容投影。空态使用合法空集合与未配置值，禁止用具体假模型补齐。对单个插件的贡献按 schema 单独验证。 |
| 管理操作 | 在原协议控制器提供同源的可安装/已安装列表、包详情、安装、配置连接、探测、启用、停用、升级和卸载操作。与现有 Advanced 管理协议共享服务；修改要求管理员、CSRF、预期修订及审计。冲突返回 409 并回读；同一请求重放返回原结果。 |
| 分发与缓存 | PostgreSQL 为授权来源。提交安装事务时同时更新安装修订和所影响的目录/价格修订，写 outbox。各进程按修订刷新缓存，浏览器刷新状态或切换工作区时重取；收到旧修订的提交重新校验。Redis 通知丢失、worker 重启也不能恢复已关闭的新准入。 |

**启动顺序。** schema 迁移和容量初始化之后只准备基础工作区、钱包及必要平台设置。移除正常安装、Compose、bootstrap、启动器和重启路径中“目录为空就安装全家桶”的逻辑。账号、账本、存储、页面和队列的健康检查在零插件情形可独立通过。镜像内的历史适配器按版本可供恢复，在当前安装关系授权前不可开始新工作。原版对照测试需要的完整插件集合通过测试夹具指定。

**事务与权限。** 安装前验证包身份、版本、依赖、能力/视图支持、schema、菜单和模型冲突。锁定安装与目录，整包登记并激活；回滚不得遗留菜单、模型或半成品连接。可安装官方包限定到发行清单，外部服务由管理员指定允许访问的端点。沿用 Vault、连接字段脱敏、受限出站目标和产物验证；允许自建内网服务时显式配置目标。平台仍独占身份、素材授权、钱包、任务状态和私有存储写入。站点安装权限、工作区使用权限、节点所有者权限分别检查。

**停用、卸载与并发。** 停用事务立即关闭新提交、配对、登记及新授权，撤去对应菜单。与并发提交在同一安装修订/锁下确定先后。已经受理的任务保留原版本执行资格，worker 只能领取停用前已固定并获准继续的任务；旧租约仍可心跳、回传及完成一次结算。立即撤销节点或凭据时按既有取消、回收和人工对账路径处理。排队、在途、结果待保存、未知提交均需有明确归宿；未清账时卸载进入等待状态，界面列出阻塞任务。卸载完成后撤销运行凭据与新请求访问，保留历史引用、账本和审计；同一插件重装不自动复活旧配对码或已撤销连接。版本升级失败可恢复上个活动版本，新旧任务各依原快照完成。

**路由和故障。** 未安装本地实例包时，原配对、安装资源、Agent 新登记和 v2 新登记直接访问返回资源不可用（建议 404）；已安装时按原协议验证会话、凭据和节点权限。对需要排空的存量节点只开放旧任务所需操作。插件未配置、上游离线、目录冲突、权限不足分别返回稳定原因；一个上游故障只影响相关模型。普通页面与历史读取不跟随上游故障返回 503。

### 贡献系统退役与旧数据处理

- **运行入口。** 从正常 Next/Nest 路径撤下 `/fmworker/*`、`/api/fmworker/*`、`/api/admin/fmworker/*` 的控制器和代理，停止分发贡献客户端。移除 `packages/platform/src/fmworker-dispatch.ts` 的资源池派发、注册表中的贡献适配器，以及用量、奖励和验证处理。旧客户端请求和缓存令牌不能产生任何派发或入账。正常实例使用的 `/connect/:file`、`/agent/*`、`/agent/v2/*` 仍由本地实例插件按原授权提供。
- **既有站点切换。** 如存在活动贡献任务，先在旧系统关停新增派发，核对已领取任务的结果、消费冻结和应结记录，再切换。结果未明的任务列入人工对账，禁止把同一请求自动重发给新实例。已经配对的贡献节点与凭据不得自动转为本地实例；需要继续使用的机器通过新插件重新配对。
- **账务和归档。** 保留已有余额、历史入账、任务及其对账依据；已发贡献收益按其原账户和记录留档。切换和重复导入均不得冲销既有余额、补发奖励或自动把独立贡献余额兑换为消费积分。迁移脚本保留已执行的历史迁移，升级使用增量变更；旧资源及凭据不恢复运行权限。原生产基线、归档源码和历史账本保持可追溯。

## 5. 兼容原数据与原界面

1. **区分三类安装。** 全新数据库进入零模型模式，建立持久的初始化标记；老 Advanced 数据库在升级事务中从已激活目录、连接、价格、节点、未完成任务和工作区策略重建安装关系；Pure/SQLite 导入使用显式兼容清单，先准备执行版本再恢复对象关系。迁移时将贡献资源标为退役，只保留历史关联。历史 `plugin_versions` 含有整批自动安装的条目，不能据此把所有可分发包标成用户安装。旧库缺少足够证据时保留原可见目录和策略，输出待人工复核项，不猜测关闭仍在用的模型。
2. **迁移前预检。** 在隔离副本列出旧公开模型 ID/内部 ID、适配器版本、活动连接、隐藏策略、价格档位、配对与节点、活动任务、冻结积分。标明每一项映射到哪个包、用于当前能力还是仅保留历史。遇到冲突或版本缺失时回滚并列明对象。原数字编号、工作区映射、现有会话体系、画布修订和私有媒体引用保持各自契约；真实凭据不复制到测试环境。
3. **历史读取独立于当前目录。** 作业展示优先读冻结快照，旧数据缺少快照时读取被历史任务引用的不可变版本。画布保存允许保留原模型及未知参数，不能因插件卸载清空旧节点；用户修改其他节点或自动保存时仍做原乐观锁检查。模板生成、重试、对话采用和续写分别核对所需能力。
4. **视觉对照分两套。** 完整兼容配置继续使用固定的 `baseline/production/manifest.json` 和 `legacy/pure/static`。对新增菜单、原 GPU 标签更名、移除贡献入口等已授权差异，单独记录精确元素、角色和视口，并验证周边布局；其余区域与交互继续原 DOM/像素对照。新增零插件/单插件状态使用独立预期与截图，不覆写原生产基线。打开旧 GPU 深链时，已安装则定位到同一面板，未安装则回到可访问的设置并解释原因。
5. **回退演练。** 记录旧发布镜像、schema 兼容范围与备份点。回退时继续封闭已退役的贡献路由和奖励写入，通过活动安装修订切回其余功能的兼容配置，保留新产生的任务、画布和积分记录。已有新写入时先停写对账，不用旧库备份覆盖新写入。合成库至少验证一次升级、重复执行、重启和回退。

## 6. 实施顺序与验收门槛

| 步骤 | 建议的交付切片 | 进入下一步的条件 |
|---|---|---|
| 1 | 给当前候选锁定完整兼容夹具；盘点启动、导入和硬编码模型；移除贡献链路并验证本地实例、生成队列和消费账本可独立工作。增加包清单、安装记录、修订和授权查询。 | 空数据库和已有安装可准确区分；并发/重复安装、模型冲突及中途失败均有隔离测试。 |

**最低验收矩阵**（使用合成数据、假上游、隔离数据库和私有对象存储）：

- **新装和重启。** 空卷、重复 migrate、重复启动及 Compose 重启后仍是 0 个已安装提供方、0 个模型。管理员可进入插件管理，非管理员不能写。直接请求 GPU 配对、登记和安装文件不会发码或返回安装内容；禁用的提交没有队列项、余额变化或外部调用。
- **贡献系统已退役。** 在空库、旧库升级、全部插件安装及重启后，插件市场与设置均无贡献入口。用旧客户端凭据访问原资源登记、用量上报、任务领取、结果回传和奖励账户接口，均返回退役或不存在，无业务写入；重复上报不会改变任何钱包。对照旧库验证历史余额和账本一致。通过本地实例与独立 Flow HTTP 服务各完成一次合成任务，用户消费只结算一次，节点所有者无新增贡献奖励。
- **本地实例单装。** 安装成功即出现「实例接入」和模型目录。按既有权限生成一次性配对、登记、心跳、领取、私有引用读取、重复回传；结果一份、扣费一次。覆盖无节点、失联、撤销、原协议与 v2，以及普通成员无法管理他人的节点。
- **Muse、Flow 各自单装。** 未配置时目录可识别、问题可定位。模拟 Muse 受理后重启继续轮询，未知提交不重复派发；模拟 Flow 分片 SSE、续写、断流与已持久回执的恢复。确认一方离线不影响另一方或工作台首屏。
- **画布参考图跨模型。** 零插件时上传一张图并保存重开；分别只安装支持图生视频的 Muse、Flow 型号或测试用第三方模型，从同一素材发起生成。检查模拟上游实际收到的图片内容与角色，再验证切换型号不重传、不复制素材。覆盖无 GPU 插件、无 Muse 插件、仅首帧、超出张数、纯文生视频和跨空间拒绝。复跑 `pnpm test:canvas-portable-references` 验证旧 H3 文档、撤销重做、保存重开和连线去重。
- **第三方和组合。** 通用示例从安装到提交、回填、历史读取均可在普通 Studio 完成。验证公开 ID 冲突、可选能力缺失、两个连接歧义、不同工作区策略、旧修订、恶意表单内容及端点不匹配的拒绝结果。管理员价格不能被重装或升级悄悄改写。
- **历史与退场。** 同时发起停用和任务提交，验证受理边界；分别在排队、执行、保存回执和待对账时停用。旧任务按冻结版本结算一次，历史素材、模型标签、草稿和旧画布仍可读写。卸载再安装不复活旧节点凭据。
- **视觉与发布。** 覆盖游客、成员、管理员，桌面与手机、深浅主题，空、单装和完整兼容配置。复跑已有 `pnpm test`、`pnpm build`、`test:studio`、`test:web`、`test:auth`、`test:home`、`test:studio:nest --routes`、`test:studio:upgrade`、`test:studio-gpu-settings`、`test:muse-lifecycle`、`test:flow-lifecycle` 及画布、计费、私有媒体专项。以固定的 120 项原路由清单为基准，另列经授权退役的贡献接口及预期不可用结果，其余路由继续原契约对照；新增插件路由单列。生产凭据、真实支付及真实提供方不作为本轮自动验收依赖。

**交接给实施者的第一项任务**：先在同一个发布候选增加两份回归夹具。一份从空卷启动并断言「插件可管理、模型为零、实例入口和发码不可用」；另一份显式安装保留的原站插件组合，通过工作台回归，并验证旧贡献凭据不能领取任务或触发奖励。以这两份夹具保护后续改动，再接通三个插件和第三方示例。
