# Muse 请求生命周期

Muse `1.10.0` 增加本地 request 插件的 `requestLifecycle: {version: 1}`。版本继承已迁移的下载、媒体验收、计时与原状态能力；安装不会自动升级已有连接或任务。核心处理租约、持久化、计费和工作区权限，Muse 的 HTTP 分类、原提示文案和响应转换留在插件中。

## 与原队列对齐

| 阶段 / 条件 | 处理 |
|---|---|
| 提交 401 / 403 / 429 | 回到排队，显示“等待 Muse 就绪”，保存 60 秒重试期限；本次计时中断，积分继续冻结 |
| 提交 400 / 413 / 422 | 原参数拒绝文案，失败并退款一次 |
| 提交其他错误、断线、无效任务编号或回执丢失 | 原“提交结果待确认”文案，失败并退款一次；记录不确定标志，绝不自动重发 |
| 已接受任务轮询 404 | 原任务记录不存在文案，失败并退款一次 |
| 轮询其他 HTTP / 传输 / JSON 错误 | 保留同一任务编号、计时、提示和冻结积分，下次只查询 |
| processing / queued / 完成别名 | 保留原阶段文案和时间同步；没有开始时间时不凭空生成计时起点 |
| 成品响应 | 按原顶层 URL、result.url、首个 data.url 的优先级选一个成品；不把额外结果扩成多个素材 |
| 下载中断 | 保存回执及保存阶段，只重试产物下载，不重新生成 |
| 素材读取 / 通用保存失败 | 分别使用原参考图错误 / 保存错误说明，不泄露内部异常 |
| 已停用账户的排队任务 | worker 取消并退款；原状态读取本身不触发请求提供方维护 |
| 全局图片关闭、提供方不可用 | 图片停止领取；不可用时排队显示原等待文案，已接受任务继续轮询 |

任务编号完整匹配原 `task_` 加 20–64 位小写十六进制规则；带尾随换行的编号也拒绝。提示词保留原 `<Picture 数字>` 转换。JSON 读取限制 2 MiB，保留 Python 接受的 UTF-8/BOM、UTF-16/32 和非有限数常量语义；不执行响应内容。提交使用稳定的 32 位幂等键，发送幂等键不被视为未知提交可以安全重发的证明。

## PostgreSQL 与插件边界

迁移 `018_request_lifecycle.sql` 添加 `request_note`、`request_retry_at` 和 `request_uncertain`。重试期限同时在候选查询和事务领取中检查，不依赖 BullMQ / outbox 唤醒时刻。租约过期但已有任务编号或成品回执时保留原执行记录；只有没有回执的派发进入提交不确定终态。

插件通过受当前租约保护的 `reportProviderNote` 写有限长度说明，通过严格的 `RequestLifecycleError` 请求 retry / poll / fail。该能力只允许已安装本地 request 适配器声明；远程 manifest 不能冒充。旧 Muse `1.9.0` 及更早版本没有该能力，继续保留旧行为。

原 `/api/state` 从持久化说明投影原 `note` 字段，排队时模型关闭的“等待模型开放”仍优先；内部重试期限、不确定标志、凭据和租约不进入原响应。终态清除临时说明和重试期限，不确定标志留作审计。这里的原 Muse 不确定终态是 `failed`，不同于旧通用引擎的 `uncertain` 人工恢复状态，不自动挂接其恢复接口。

## 验证及边界

`pnpm test:muse-lifecycle` 直接运行不可变原 `muse_provider.dispatch_one` / `poll` / `complete` 和 SQLite 计费触发器，以临时数据、替换 HTTP 的方式生成 82 个场景、126 个状态快照；新实现分别使用隔离 PostgreSQL 和 PGlite 对照任务状态、原说明、次数、重试、不确定标志、计时阶段、积分及请求/成品选择。测试对照不依赖复制生产配置或调用真实 Muse。

平台测试另覆盖并发领取、重试期限、冻结配置、旧租约写入拒绝、进程中断恢复、参考素材变化后继续轮询、图片/账户开关、原状态说明、下载恢复、私有文件保存、一次结算、插件版本隔离及 JSON 边界。相关回归包括原状态、提供方时间、下载、Next/Nest 和原工作台集成。

对照结论限于已测试路径。Flow/图片完整异常生命周期、资源管理、其余原业务以及工作台/画布 React 迁移仍未完成。默认 `/studio` 仍由 Next 提供原工作台并使用 Python 兼容业务后端；此次修改不切换 UI 或混接两套会话/数据库，也不代表整站技术栈迁移完成。
