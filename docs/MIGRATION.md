# Pure → Advanced 迁移

## 基线与边界

基线来自 `ninjaz0/fumiao-aigc-pure` 的 `167896e59196adc2d96a816191b02d3f4561f605`。之前核对了 nvmes.com 的部署副本：主平台共享文件 130 个一致、11 个不同；伴生 Flow 和 Muse 也有线上修复。比较结果见 `代码比对与插件化重构方案.md`。本次保留上游平台行为，并将线上依赖更新、Flow 管理面安全修复和 Muse 消息发送修复一起保存到 `legacy/pure/`。

新仓库不包含服务器密钥、账号库、提供方凭据或生产 SQLite 数据。没有修改 nvmes.com 的运行版本。

## 原版 UI 兼容状态

本机默认入口由 Next.js 提供。官网首页、登录/注册、已登录的 `/studio`、画布列表和 `/canvas/:id` 默认由 React / TypeScript 渲染，验收使用固定生产版 DOM 和截图。工作台可用 `/studio?studio_ui=legacy` 显式回退。开发和生产预览及 Compose 默认通过 Next 连接持久原协议 Nest 后端，可通过 `STUDIO_BACKEND=python` 显式启用兼容服务。固定清单内 11 项由 Next 提供，95 项由 Nest 经网关提供，14 项旧贡献方法在网关返回 410。目标部署仍待验收。[原协议 Nest 持久预览和隔离验收](ORIGINAL_NEST_STUDIO.md)

接口分组和完成标准见 [UI 一致性迁移](UI_PARITY_MIGRATION.md)。

| 对话 | 原 REST/SSE、PostgreSQL 会话及账本、BullMQ 流式执行、历史导入和画布写回 | 已验证 React 工作台和编辑器的 SSE 与写回。默认后端为原协议 Nest |
| 素材包 / 收藏 | 新工作台管理 | 导入旧数据 |
| 分镜合成 | 原协议 Nest 导出与字幕/镜头下载、BullMQ 队列和版本化 FFmpeg 插件 | 已验证画布内成片、历史、字幕及私有下载 |
| GPU 原生参考 | 文生视频、图片及音视频参考、首尾帧、文生语音 | React 编辑器的 H3 控件已与原版差分对照 |
| fmWorker / Colab | 原客户端源码完整归档 | 旧贡献资源与收益按历史资料对账。见[退役范围](FMWORKER_RESOURCES.md) |

这是新版主平台和插件体系的可运行基线，不应把尚未迁移的交互视为已经完成。上线前按这张表逐项验收决定切换范围。

## 迁移前

1. 在独立目标上完成 `API_PROTOCOL=original pnpm db:migrate`，Docker 使用 `docker compose up --build migrate`。使用空 PostgreSQL 及专用私有对象目录或桶。设置 `STUDIO_LEGACY_SOURCE` 为该实例的稳定标识，并与 `--source` 一致。已有工作区需直接导入，`bootstrap` 会拒绝配置了来源标识的目标库。
2. 原站暂停写入，等待生成、对话和合成完成，核对未确认任务及充值订单。积分（含贡献合格积分）冻结须为零，过期但未核对的订单也须处理。
3. 使用 SQLite 备份 API 或停止写入后的等价一致性快照，和同一时间点的对象及头像备份一起留存。SQLite 使用 WAL 时仅拷贝运行中的主文件无法保证完整。工具读取备份，导出另存为新文件。
4. 记录旧库和对象恢复点，限制目标的业务流量。保留同步的媒体备份、旧导出及目标配置供复跑和对账。

### 节点与充值分支的数据库升级

运行 `pnpm db:migrate`，随后对新目标库执行 `pnpm import:legacy`。已有 PR12 或 PR13 数据的目标库只需运行同一个迁移命令。迁移账本使用完整文件名，因此 `027_original_node_management.sql` 与 `027_original_recharge.sql` 均沿用已发布的文件名；事务内只执行缺少的文件。节点升级保留已有配对和编号。充值升级在已有身份、工作区与钱包之后从 `legacy_records` 恢复历史订单，原账本和余额保持原值。新导入在同一事务中写入节点名、身份和账本，归档充值记录后再恢复订单。空库、仅应用节点迁移、仅应用充值迁移以及重复运行均有隔离 PostgreSQL 回归测试。

## 导出与导入

```sh
python3 scripts/export-legacy.py \
  --database /backup/pure/studio.sqlite \
  --source nvmes-production \
  --include-registration-codes \
  --objects /backup/pure-objects \
  --avatars /backup/pure/avatars \
  --output /backup/pure-export.json
```

导出文件含密码哈希、可用邀请码等敏感信息，创建权限为 0600，禁止提交 Git。导出器拒绝仍有活动任务、冻结积分和未关闭充值订单的数据库。完整迁移须指定 `--include-registration-codes`；未包含邀请码的导入会在写入前报错。

媒体应以旧媒体 ID 为文件名，放在一个目录下。旧磁盘模式对应 `.data/objects/`；旧 COS 模式应从 `studio/` 前缀下载对应对象到本地目录，不能将公开 URL 当作完成的媒体迁移。

磁盘备份需保留修改时间（例如用保留时间的复制命令），导入据此保留原 `Last-Modified` / `ETag`。`--objects` 校验每个旧媒体文件的大小并将 SHA-256 和纳秒修改时间纳入导出指纹。头像的大小、哈希及时间也保存在导出清单中。对已成功导入的旧版清单复跑时继续使用同一份导出文件；带新增校验字段的清单会生成另一指纹。

```sh
export LEGACY_EXPORT=/backup/pure-export.json
export LEGACY_OBJECTS=/backup/pure-objects
export LEGACY_AVATARS=/backup/pure/avatars
pnpm import:legacy
```

本机可用 `node --env-file=.env.studio-nest --import tsx scripts/import-legacy.ts` 为独立目标选择配置。Docker 可在迁移完成后使用一次性容器，只读挂载包含导出、媒体和头像的目录。

```sh
docker compose run --rm --no-deps -v /绝对路径/pure-backup:/backup:ro \
  -e LEGACY_EXPORT=/backup/export.json -e LEGACY_OBJECTS=/backup/objects \
  -e LEGACY_AVATARS=/backup/avatars api pnpm import:legacy
```

导入按来源和旧 ID 生成稳定内部 UUID，保留公开数字编号和 32 位媒体编号。它校验清单、复制媒体与已上传头像、恢复默认空间和修订号，并推进新编号序列。同一导出可重复执行；已成功导入的相同指纹返回 `alreadyImported: true`。已导入的同一 `source` 若指纹变化，程序在写入对象前拒绝运行。一次性容器的 `node` 用户须能读取挂载的备份文件。

数据库事务先串行锁定导入和初始化，再校验目标、复制对象并写入记录。导入中断时可能留下未引用对象，在同一专用目标中重复导入可复用对象键。数据库不会保留半批账号或账本。导入是一次完整快照，也可重复演练；上线前需暂停旧端写入以防数据分叉。

## 验收和切换

- 核对用户、工作区、素材、历史任务计数；逐个比较工作区余额，冻结应为零。
- 用普通用户验证个人/团队隔离、历史媒体、画布、素材包及旧密码登录。
- 核对已恢复的模型目录、全局/团队开关、用户隐藏模型、分档价格及修订号。插件连接和商户凭据仍需重新配置；导入不会启用真实提供方连接。
- 对每种真实提供方各做一次受控生成，对 GPU 检查断线恢复和结果回传，对支付做网关测试订单。仓库的协议测试使用模拟上游，不代替这些验证。
- 完成预期负载下的排队、连接额度、数据库连接数、存储吞吐测试，再将反向代理切到新站。

若尚未接收新写入，可恢复原站直接回滚；一旦新站产生充值、积分消耗或新作品，必须先停写并对账/导出新数据，不能直接回滚造成余额和作品丢失。建议两站独立数据库，避免共用旧 SQLite。

旧会话在 Nest 侧失效，用户用旧密码登录并取得新会话。创作草稿保存在原标签页的 `sessionStorage` 中。同一站点 origin 和标签页下，重新登录后使用保留的用户/工作区编号读取。邀请码、兑换记录、账本、上传头像和素材包恢复为可用记录。遇到与团队名称或个人空间唯一性冲突的已有记录时，SQL 迁移会中止，待在独立副本中核对。

邀请码在 PostgreSQL 中加密存放，查询哈希及使用次数、有效期、角色、赠送策略、团队、修订号和兑换记录一同保留，归档记录不保留邀请码明文。账本保留原数字编号、操作人、任务编号、对话轮次、原因、幂等编号、操作时间和每条余额/冻结快照；导入前核对每个钱包与最后一条历史快照，发现不一致即拒绝导入。已有原账本的空间不另记一笔开账收入。

原任务保留公开数字编号，内部 UUID 与禁用的历史提供方连接不变。新注册、调整、冻结、结算、退款和充值写入相同账本及快照。PostgreSQL 序列允许回滚后的编号空缺；已导入和已发出的编号保持稳定。

新导出包含 `job_runs` 计时白名单。导入保留尝试、阶段时间、预测及匿名样本，重新映射任务/节点身份；可识别模型关联版本化插件计时策略，历史任务仍不可派发。早期缺少计时表的导出不会获得虚构样本，完整补齐须重新导出到新的隔离目标库。范围与验证见 [任务计时迁移](TIMING_MIGRATION.md)。

完整新导出另带有 `stateVersion: 1`，保留素材原 `rowid` 顺序、节点公开信息及归属、历史任务执行次数和节点编号、原默认团队与图片启用开关。导入节点被强制禁用，不导入节点密钥；真实 GPU 须重新登记。旧开发库中无法确定的归属、顺序或执行次数保持未知，不能据此宣称状态迁移完成。字段、升级边界和隔离原服务对照见 [原状态数据迁移](ORIGINAL_STATE_DATA.md)。

完整对话导出新增 `chatVersion: 1`，包含原会话顺序、隐藏消息、软删除状态、轮次、费用、画布链接与采用历史。CLI 要求此标记；旧导出需重新导出到新的隔离目标库。关联校验、原始文本归档、账本绑定与删除画布后的采用记录均在 [原对话存储与执行](CHAT_CONVERSATIONS.md) 说明。`pnpm test:chat-import` 已验证原记录及导入后 30 个操作，完整画布导入见下文。

画布的 TypeScript 输入解析、图结构/引用校验和版本化插件规则已通过独立对照：324 个输入场景、6,247 个规则场景及 55 个模板选型。随后新增原画布 UTF-8 文档、基本操作、修订保存和引用关系，61 个原服务操作快照及并发/回滚测试通过。完整导出现要求 `canvasVersion: 1`，包括原画布、素材引用、任务链接、候选批次、合成历史及合成引用六张表。导入保留原文、公开编号和历史关系，已通过 36 个导入后原服务操作对照。旧通用 JSONB 投影不会自动转换成原文档；须用新导出导入新的隔离目标库。生成、导出、对话采用和画布 HTTP 已接入原协议 Nest 服务，React 编辑器也已完成隔离验收。参见 [原画布存储与基本操作](UI_PARITY_MIGRATION.md#原画布存储与基本操作隔离验证)。

后续独立 Nest 应用已实现原生成提交、估时查询及完整状态聚合，状态投影由新版本提供方插件声明。`test:state` 对比管理员、团队成员、个人空间及活动任务，保留原公开字段、排序与权限；所需插件须显式激活且连接无歧义。上文的状态数据缺口已在 [原状态聚合接口](ORIGINAL_STATE.md) 记录的范围补齐。普通配对通过原协议 Nest 执行。实际部署仍需在目标环境验收。

收藏导入保留原用户、任务/素材归属、时间及顺序。迁移后的批量删除隐藏已结算任务并移除相关文件，不删除账本和任务幂等记录；已接受请求重试不会重新生成或扣费。下载票据和旧登录会话均不导入，用户重新登录后可重新生成私有下载链接。

模型设置从白名单 `model_policy`、`hidden_model_ids`、`credit_price_revision` 和原价格/团队策略表导出。导入与账号、账本处于同一事务，按插件目录核对全部模型和档位；缺少策略/修订或档位不一致会报错并回滚，不能用默认价格替代原价格。含旧价格但缺少新白名单设置的早期导出文件需重新导出。


新数据库默认全局媒体容量为 20,000,000,000 字节；迁移前用 `FUMIAO_QUOTA` 明确配置与原站相同的上限，`pnpm db:migrate` 将其持久化。导入媒体同样受事务容量约束；超过上限会回滚数据库导入，不能通过忽略素材或删除用户数据让迁移通过。源容量配置和媒体大小须在切换验收中核对。


原画布生成内部服务通过 `OriginalGeneration.submitOn` 将任务、冻结、发件箱和画布链接纳入同一事务；双候选第二条失败不会留下第一条。Muse `1.12.0`、Flow `1.11.0`、GPU / 图片 `1.10.0` 以声明式 `canvasSubmission` 控制默认模型、原生 H3、固定采样和运行标签，安装不自动启用。95 个原版生成/运行场景、36 个历史导入后操作以及并发/回滚验证见 [原画布生成与运行记录](UI_PARITY_MIGRATION.md#原画布生成与运行记录隔离验证)。这些内部契约已接入原协议 Nest 和 React 编辑器，组合验收见 [画布编辑器一致性](CANVAS_EDITOR_PARITY.md)。
