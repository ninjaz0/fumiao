# 原对话提供方与配置迁移

`compatible-chat@1.2.0` 增加本地 `chat` version 1 能力，保留原 DeepSeek / OpenAI 的流式请求、标题请求和连接测试。提供方名称、模型、默认地址、备用凭据来源及协议处理均由插件声明或实现。核心负责身份、空间、目录策略、加密连接及审计，不按提供方名称分支。

提供方传输、上下文构造和原配置接口已完成隔离验证。后续新增的 PostgreSQL 会话存储、一次计费及 BullMQ 后台执行见 [原对话存储与执行](CHAT_CONVERSATIONS.md)；完整原会话历史已支持导入；SSE、画布采用及发送 HTTP 路由仍未接通。默认 `/studio` 仍使用 Python 兼容业务后端，工作台/画布仍有原 JavaScript；没有切换默认路径或修改固定 UI 基线。

## 插件边界

Manifest 的 `chat.providers` 声明服务 ID、标签、模型列表、默认连接配置及可选备用凭据。适配器实现 `chatProvider`、`chatConfigured`、`chatConfigure`、`chatStream`、`chatTitle`、`chatProbe`。只有已安装的本地适配器能声明该能力，尚无远程聊天插件协议。安装不自动激活目录、升级连接或改写旧任务。

一个连接对应一个声明的服务，只关联它的模型；从旧通用连接升级时，其余模型保留为停用记录并解除目录关联，已接受任务的引用不删除。原设置接口只允许每个活动版本/服务存在一个连接，歧义返回 503。Advanced 普通配置和升级均不能把已有的服务身份换成另一服务；需要另建连接。原配置保存与连接创建/升级使用同一事务锁，首次并发保存只创建一次连接。

该版本的流式接口用于独立会话执行器，旧开发版媒体任务入口不会调用它生成回复。旧 `1.0.0` / `1.1.0` 的请求行为继续保留。

## 传输与上下文

- 流式请求沿用模型、消息、4096 token 上限、用量开关及原 DeepSeek thinking 配置。连接超时 15 秒，读取空闲超时 90 秒，不跟随重定向、不自动重发，不使用环境代理。
- 按原 SSE 的 `data:` 前缀、DONE、Python 分行/空白/JSON 规则解析；保留指定的五个整数用量字段，过滤浮点数、布尔值和未声明用量，不传递隐藏推理。大整数在内部用 bigint 保持精度，后续持久化必须按原整数文本序列化。
- 保留原 1 MiB 单行限制及错误分类。超长未结束行不持续占用内存，在原换行或 EOF 边界才报告长度错误；若此前连接中断，仍按中断处理。gzip、zlib/raw deflate 与原固定环境的协商一致。取消/关闭迭代器会关闭底层请求和解码器。
- 标题请求沿用首轮各 4000 个 Unicode 字符、64 token 上限和原提示词；保留 finish reason、前缀/引号清理、空白合并、控制字符及 40 字符结果限制。连接/读取超时分别为 5/12 秒。首轮资格、手动改名保护与 15 秒外层时限由独立会话执行器负责。
- 上下文仅保留完整历史问答及当前用户消息，按原顺序执行 20 组 / 50000 Unicode 字符预算；当前画布文字包装与 writeback 系统提示不变。调用者必须提供已按编号排序、排除 superseded 且截至当前用户消息的记录，不能把未完成回复或隐藏推理送入上下文。

## 原 HTTP 接口

独立 Nest 原协议应用提供：

| 方法与路径 | 行为 |
|---|---|
| `GET /api/chat/config` | 当前空间可用模型、原完整分档价格与钱包；遵守全局/团队策略及凭据状态 |
| `GET /api/admin/chat` | 管理员读取服务标签及 configured，绝不返回密钥 |
| `PUT /api/admin/chat/{provider}` | 先认证管理员，再读取原 JSON 字节；严格密钥格式/额外字段检查；加密保存且不改变模型/价格修订 |
| `POST /api/admin/chat/{provider}/test` | 忽略请求体，检查管理员/服务/凭据；插件在事务外探测原模型列表，保留原 409/502/普通文本 500 |

配置保存在 PostgreSQL 加密连接中，不创建新的 `chat.env` 或复制线上凭据。OpenAI 的图片凭据回退由插件元数据声明，读取活动图片插件已验证的凭据，仅在本次内存配置中合并，不复制到对话连接。显式对话密钥优先；配置探测不会创建任务、冻结积分或改写健康状态。首次通过原设置保存的连接可用，与旧“配置密钥后可使用”行为一致；Advanced 显式停用的既有连接仍保持停用。

## 验证

`pnpm test:chat-provider` 调用固定原 `chat_runtime` / `chat_api`，使用临时 SQLite 和 httpx MockTransport，与本地 HTTP 上游下的新插件对照：181 个协议/错误/标题/编码/探测场景，30 个上下文场景。比较返回事件、安全错误、提供方请求体/路由/鉴权与压缩协商。

`pnpm test:chat-settings` 对照真实原 FastAPI 和 Nest 的 81 个 HTTP 场景，比较状态、JSON/文本、Content-Type、Allow、配置状态、策略修订及上游调用。既通过随机 PostgreSQL schema，也通过临时 PGlite。

平台测试另覆盖空闲超时、压缩流取消、无重定向/重发、隐私字段过滤、原权限顺序、密钥加密、备用凭据不落库、并发首次保存、连接歧义、版本隔离与升级模型绑定。测试只使用合成密钥和本地模拟服务。共享 Python JSON 解码器移至 SDK，Muse 原导出路径保留；原 Muse 的 82 场景 / 126 状态、积分、计时快照回归通过。

这些结果只证明上述提供方和配置范围，不代表原对话业务或整体技术栈迁移完成。
