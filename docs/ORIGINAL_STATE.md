# 原状态聚合接口

独立 Nest 原协议应用已挂载 `GET /api/state`，在 TypeScript/PostgreSQL 中汇总原工作台所需的完整字段。默认 `/studio` 连接原协议 Nest。React 工作台候选和部署验收详见 [原协议工作台验收](ORIGINAL_NEST_STUDIO.md)。

## 插件能力与版本

GPU `1.8.0`、Muse `1.7.0`、Flow / 兼容图片 `1.6.0` 新增 `originalState: {version: 1, ...}`。安装不自动激活目录或升级连接，任务继续固定接受时的插件版本。新能力仅允许已安装的本地适配器；远程 HTTP 插件的状态扩展协议尚未实现。

- `fields` 声明拥有的原公开配置字段；`configuration` 返回固定结构。加密连接配置仅交给本地 `configured` 纯函数判断，公开投影只收到布尔值、健康缓存和目录，不收到密钥。
- `queueLane` 声明前方任务计数按生成类型或插件分组。Muse 的图片和视频共享队列，GPU 的视频和音频分别计数；跨工作区任务只影响计数和预测，不返回其他空间的内容。
- `project` 从冻结的原参数、执行阶段及已校验产物元数据生成说明和实际结果字段。核心不按提供方名称分支。
- `outputKinds` 保留新版本图片产物作为原参考素材的规则；旧版本的产物角色不变。
- GPU 的 `recovery` 声明中断重试上限和原说明。首次租约过期重新排队，第二次失败并只退款一次；旧租约不能继续上报。已收到回执的任务继续保存，避免重新派发已有结果。旧 GPU 版本仍保留其原有异常处理。

完整状态要求所有原配置字段各有一个适配器负责，且对应版本的连接不存在歧义。缺失能力、重复字段或多个连接返回 503；不会随机选择连接或返回删减字段的成功响应。多个连接的统一原界面配置设计仍需另行实现。

## 一致性与权限

每次读取在同一 `REPEATABLE READ` 事务内重新校验账号和工作区，处理具备新恢复能力的过期 GPU 任务，再读取队列、公开节点、素材、历史和活动任务、目录、策略、余额、账本及收藏。冲突时至多重试三次；重试不重复退款。只有管理员响应含用户、邀请码、团队策略、积分账户和全局容量。

公开编号和新 UUID 通过原身份适配统一解析。个人空间、节点归属、素材原顺序、历史空值及原默认团队沿用 [原状态数据迁移](ORIGINAL_STATE_DATA.md)。无法确定的历史字段仍报迁移错误；不能将早期开发原型任务伪装为已完整迁移的原任务。旧会话及节点凭据不恢复。

管理员 `disk_free` 读取当前私有磁盘目录的真实可用空间；S3 模式显示本机临时处理目录的可用空间，媒体配额仍以 PostgreSQL 容量记录为准。保存全局模型策略时同步原图片总开关；新图片插件在生成前校验该开关和原配置有效性。

## 验证与剩余范围

`pnpm test:state` 先运行历史数据的 7 项验收，再启动隔离原 Python / Nest 服务，比较 27 项完整 HTTP 快照和契约：管理员、团队成员、个人空间、访问拒绝、HTTP 方法、未配置及已配置提供方、健康缓存新鲜/过期/未就绪、七类队列任务、跨空间计数、停用模型、图片总开关，以及 GPU/Muse/Flow/图片运行阶段。报告为 `.runtime-advanced/state-parity/report.json`。

对照保留全部公开字段。两次 HTTP 请求的 `server_time` 先检查误差小于五秒；运行中计时另用不可变原 `timing.attach` 在相同时间点计算，直接只读 SQLite，避免导入原应用触发初始化写入。磁盘可用量验证为正整数且两次差异小于 128 MiB，随后对齐这项随运行环境变化的值。其余响应逐字段严格比较。

平台测试覆盖四组行为：完整权限/公开字段和配置隐私、并发过期恢复/旧租约拒绝/一次退款、新图片执行与参考列表/旧版本保持、远程能力拒绝/配置投影错误/连接歧义。数据库与媒体均为临时数据，不读取生产凭据，不调用真实模型或支付。

当前阶段验证了状态聚合和上述任务流。Muse/Flow 完整错误与重试协议、全部产物格式验收、资源池清理、并行 GPU 与客户端管理、画布和其余业务契约仍需继续迁移。运行阶段对照使用等价合成记录，不能代替真实上游所有异常路径验收。默认后端的组合验收见 [原协议工作台验收](ORIGINAL_NEST_STUDIO.md)。

## 原节点管理

独立 Nest 原协议支持以下普通 GPU 节点契约。

| 端点 | 行为 |
| --- | --- |
| `GET /api/pairs/default-name` | 登录后预览全局递增名称 |
| `POST /api/pairs` | 登录后按原模型顺序生成有效期 30 分钟的安装命令 |
| `POST /api/nodes/{i}/{action}` | 管理员按原公共编号执行 `drain`、`resume`、`stop`、`remove` |
| `POST /agent/enroll`、`GET /agent/registration` | 配对码绑定一个节点，原凭据可重试读取自己的回执 |
| `GET /connect/{file}` | 提供原 `install.sh`、`agent.tgz` 和 `agent.tgz.sha256` |

配对复用当前激活的 GPU 插件版本和唯一匹配连接。SQLite 导出保留原节点编号、编号名称的计数和配对占用名称。旧配对和旧节点凭据需重新签发。新配对码和节点凭据以哈希存储。注册查询只向节点返回自己的原协议配对摘要。注册校验错误对输入值脱敏。

停止或移除节点时，首次中断保留同一任务和积分预留并重新排队。第二次中断记录计时并只退款一次。NestJS 原协议入口支持普通配对节点的 `/agent/heartbeat`、`/agent/claim`、`/agent/jobs/*`，以及通过 `X-Model-Lane` 运行的独立视频和语音通道。领取和回传使用对外任务编号、素材 ID 和票据，后台使用 PostgreSQL 的 UUID 与租约。BullMQ 进程沿用同一租约回收逻辑，成片经任务固定版本的插件验收后结算到提交空间，素材通过私有存储交付。普通配对沿用原版的全局派发和无贡献奖励行为。可将 `ORIGINAL_GPU_DISPATCH_PAUSE_FILE` 指向部署侧标记文件，创建文件时暂停新领取，已领取的任务继续执行。
`pnpm test:nodes` 使用 `STUDIO_PYTHON` 指定的解释器（默认工作区的原版 venv）和独立数据库做真实 HTTP 对照。设置 `TEST_DATABASE_URL` 可使用随机 PostgreSQL schema。对照使用合成 PNG、WAV 和 H.264/AAC 成片。默认工作台同样使用原协议 Nest。旧贡献资源及收益的范围见[退役说明](FMWORKER_RESOURCES.md)。

在 Next 原站模式中，`/connect/*`、`/agent/enroll`、`/agent/registration` 及执行端的 `/agent/heartbeat`、`/agent/claim` 和 `/agent/jobs/*` 与 `/api/pairs` 使用同一 `LEGACY_API_INTERNAL_URL`。显式接入原协议 Nest 时，将该地址指向 `API_PROTOCOL=original` 的进程。`/agent/v2/*` 仍由 `API_INTERNAL_URL` 指向的 Advanced API 提供。两组路由已在独立后端之间验证。
