# 提供方成品验收

Muse `1.9.0`、Flow `1.8.0` 增加 `artifactValidation: {version: 2}`，在已迁移的下载协议之后校验媒体，再由平台保存到私有存储和结算。该版本面向本地 request 插件；GPU 的 version 1 pull 验收协议及已接受的旧任务保持原行为。安装不自动激活目录或升级连接，默认工作台未切换。

## 保留原文件和元数据

图片只接受原 PNG/JPEG/WebP 范围，保留 3200 万像素上限，实际解码首帧后才允许入库。EXIF 方向影响公开宽高，但不会重新编码或旋转原文件。动画图片按原首帧验收，格式/尺寸错误与无法解码的错误保留不同的原说明。

图片检查复用有界的 Node 工作线程队列，转换和检查共享并发上限；队列繁忙或工作线程暂时不可用时保留已接受回执、保存阶段和冻结积分，释放本次租约等待重试，不重新生成或退款。原参考图片/头像转换继续使用原有分支。

视频按文件头选择 MOV 或 Matroska 解复用器，FFprobe 校验首个视频流的宽高、时长和旋转信息，FFmpeg 实际解码首帧。保留原宽高 1–8192、时长大于 0 且不超过 120 秒的规则，以及 MP4/MOV、WebM/Matroska 的原 MIME 判断。实际元数据包含宽高、三位小数的时长及原帧率字符串；存储的仍是下载原字节。

新 Flow 版本没有上游媒体编号时不输出 `flow_media_id: null`，与原 `output_metadata` 的省略规则一致。无效产物转为终态失败，释放容量和积分且只退款一次，不保存损坏素材。Flow 恢复已有回执时沿用原恢复保存的统一错误文案。

## 验证

`pnpm test:provider-media` 在临时目录生成 74 个合成文件，调用固定原 `muse_provider.inspect_media` 获得预期结果；新 Muse/Flow 验收分别覆盖首次和恢复保存，共 296 项元数据/错误对照。包括三种图片格式的八种 EXIF 方向、动画及默认 APNG、色彩模式、已识别但不支持的格式、CRC/截断/空文件、像素上限，以及视频容器、方向、尺寸、时长、纯音频、短视频及损坏文件。所有输入字节在检查前后保持一致，报告位于 `.runtime-advanced/provider-media-parity/report.json`。

平台四组执行回归使用隔离 PostgreSQL/PGlite 和本地 HTTP 假服务，验证 WebM 私有保存与原状态字段、EXIF 文件/参考素材角色、错误退款和容量释放、远程能力拒绝/版本匹配、Flow 恢复错误以及校验繁忙后不重复生成。原图片上传的 116 项格式/像素对照和工作线程取消/队列/超时测试也继续通过。

这里没有调用真实提供方或支付，也没有使用生产凭据。验收结论限于上述输入和执行路径；Muse/Flow 完整提交、轮询与准入异常、资源管理及原 UI 的 React 迁移仍待完成。默认 `/studio` 仍使用 Python 兼容业务后端，不能据此宣称整站迁移完成。
