# 原生成提交契约

独立 Nest 原协议应用已实现 `POST /api/jobs`、`POST /api/image-jobs`、`POST /api/audio-jobs`。请求、公开编号、权限、任务持久化和积分事务均由 TypeScript/PostgreSQL 处理；原 Python 服务仅作为隔离测试参照。这三个接口现由默认 React 工作台经 Next 调用，并与状态、画布和资源管理共享原协议 Nest 会话。

## 插件与执行连接

`originalSubmission: {version: 1}` 是版本化本地插件能力：GPU `1.6.0`、Muse `1.5.0`、Flow `1.4.0`、兼容图片 `1.4.0`。插件分别声明原请求命名空间、验证顺序、参考素材角色、排队上限和输入冻结规则。核心只处理授权、事务、目录价格、容量、任务和队列，不按提供方名称分支。远程插件不能声明这项本地能力；已有远程执行契约保持可用。

远程 request 插件可以声明 `originalSubmission: {version: 2}`，由固定适配器转换默认工作台的图片、视频和语音请求。远程任务使用相同的素材授权、价格校验、冻结与队列事务。模型格式和本机安装步骤见 [默认工作台运行示例](PLUGINS.md#默认工作台运行示例)。

安装新版本不会激活目录或升级连接。按 [插件升级](PLUGINS.md#升级与停用) 显式激活后，原生成入口要求每个模型在该工作区恰好存在一个可用的匹配版本连接；没有连接或多个候选返回 503，不随机选择。多个连接的原站绑定配置尚待提供方管理面迁移。Advanced 的显式连接/模型选择仍可独立使用，已接受任务固定旧插件版本和配置快照。

## 公开身份与原子提交

- 请求保留原数字父任务编号、32 位素材编号、素材包修订和 UUID 格式的 `uid`；在权限检查后解析为内部 UUID。H3 原生输入的公开视图和执行清单分别保存公开编号与 UUID，不混用外键。
- 原 UID 在用户与插件声明的命名空间内唯一，跨工作区重试仍先校验原任务访问权。按原验证顺序，合法重试返回第一次创建的编号，即使提示词、参考图或价格修订后来改变，也不重复冻结积分。素材包重试与普通请求的验证顺序保持区别。
- Advanced 的工作区请求摘要和幂等键保持原规则。原任务删除仍保留账本及内部墓碑；部分唯一索引允许已删除的原 UID 创建新任务。迁移 `016_original_generation.sql` 补齐已经导入的历史 UID、父任务、原参数视图和提交估时，新导入也保存这些字段。
- 原父任务继续使用公开数字编号，保留父任务删除后的历史关系。H3 在未显式选择采样步数时继承同模型父任务的有效步数；其他模型保留原类型限制。素材包内容与修订、参考输入及 Flow 续写来源在提交时冻结，后续编辑不会改写任务。
- 两种提交协议共用同一个原子接受函数。任务、积分冻结、账本、素材关联、容量预留、事件和 outbox 在同一事务提交；权限、价格、余额或配置失败全部回滚。用户级 UID 锁和插件级准入锁防止并发重复创建或突破原排队上限。

插件只收到已授权的参考元数据、父任务/来源摘要和有限的容量/准入回调，不收到数据库或凭据。核心再次验证返回参数 schema、引用集合和准入条件。图片插件冻结原站地址与公开用户编号的 SHA-256 请求标识，并保留 `<Picture N>` 的原上游提示词转换；Flow 插件保存媒体来源编号并发送原 `extend://` 输入。旧插件版本的请求不会因这些新规则改变。

## 提交估时与验证范围

提交事务冻结已有计时/队列插件的估算结果。无历史、无 GPU 节点时保持原 `source`、`samples`、`confidence`、`reason` 和版本字段；不会为填充估算而调用提供方。后续版本已补齐 [独立估时查询](ORIGINAL_ESTIMATES.md)，完整 `/api/state` 以及完整 GPU 资源协议仍待迁移。本阶段也不宣称所有提供方错误文案、成片处理和管理界面已与原版完全一致。

运行 `pnpm test:generation`，需要已准备的固定 Python 参照环境；可用 `STUDIO_PYTHON` 指定该解释器。使用 `TEST_DATABASE_URL` 时建立临时 PostgreSQL schema，否则使用 PGlite。测试在临时 SQLite 中关闭派发，再导出合成账号和素材到新库；不可用的本地连接及占位密钥仅用于配置判断，不调用真实提供方。音视频角色用合成元数据验证输入冻结，真实转码和成片另由 `test:references` / `test:native` 验证。

当前 91 项真实 HTTP 和任务快照对照覆盖请求错误及顺序、原编号/UID、父任务继承、H3 混合输入、素材包冻结、Muse/Flow/图片参数、提交估时和余额变化。平台测试另外覆盖并发幂等与准入、删除后 UID 重用、跨空间拒绝、伪造插件输出、连接歧义、余额不足回滚、历史迁移，以及本地假 HTTP 提供方的版本化请求。报告位于 `.runtime-advanced/generation-parity/report.json`。

这些测试不替代完整 UI 验收。固定生产基线和原静态文件保持不变，最终入口仍须在相关原协议及 React 交互全部通过对照后整体切换。
