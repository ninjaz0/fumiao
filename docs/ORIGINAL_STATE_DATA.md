# 原状态数据迁移

本阶段补齐完整 `/api/state` 所需的历史数据。后续已实现独立 Nest 状态聚合接口，范围和版本能力见 [原状态聚合接口](ORIGINAL_STATE.md)。`OriginalStateRecords` 为该接口提供节点、素材及归档任务查询。默认 `/studio` 仍使用 Python 兼容业务后端，工作台和画布的 React / TypeScript 迁移也尚未完成。

## 保留的数据

迁移 `017_original_state_data.sql` 与新版导出/导入共同保留：

- 节点公开数字编号、归属用户、名称、状态、详情、控制状态、模型、就绪模型和硬件描述。节点内部 UUID 与既有计时记录的映射一致。管理员能看到全部未删除节点，普通用户只看到自己贡献的节点。
- 素材在原 SQLite 中的 `rowid` 顺序。该顺序与随机媒体 ID、文件时间无关；新素材序列从已导入最大顺序号之后继续。工作区过滤和音视频参考元数据保持不变。
- 历史任务执行次数、原节点编号、公开参考编号、原创建/更新时间、说明及结果编号，保留原数据中的空值。历史任务继续绑定禁用的归档连接，不能重新派发。
- 原默认团队编号与图片启用开关。它们与提供方密钥分开导出，图片开关不从全局模型策略推测。

节点接入码现在记录创建者，新节点继承其归属；可选心跳详情与已有硬件/队列上报一同保存。任务只在新的实际执行领取时增加次数，轮询或恢复同一次请求的租约不会增加次数。这些是持久化补充，不改变已有插件版本的提供方请求或自动升级连接。

## 导入边界

完整的新导出带有 `stateVersion: 1`。导入前校验节点归属、公开编号、素材顺序唯一性、执行次数和公开设置；缺失必要字段时拒绝导入，不先复制媒体或写入账号。原导出文件仍为 0600 权限。

节点导出只包含白名单公开信息，不含原节点密钥、有效期或活跃票据。任务和计时记录也不保留票据；导入端再次过滤节点字段及任务票据，防止手工归档绕过导出白名单。归档节点使用新的不可复用凭据摘要，并被数据库约束禁止启用；接入真实 GPU 仍须重新登记。原已移除节点保留历史身份但不出现在状态列表。

已有 Advanced 数据升级时，仅从可验证的计时和归档记录恢复执行次数、公开节点及素材顺序；无法确定的值保留为未知。旧版导出缺少的节点归属或媒体顺序不能从随机 UUID、统一导入时间或当前管理员身份推断。相关内部状态查询会报告缺失。需要重新从原只读备份导出到新的隔离目标库进行完整验收，不能删除已有开发数据来使检查通过；同一来源内容变化仍会拒绝覆盖导入。

历史节点在新库中禁用，因此节点公开信息一致不代表原工作进程已经接入新执行协议。后续状态能力已补充提供方公开配置、活动任务投影、GPU 中断重试、图片参考角色及管理员汇总；资源管理、完整提供方异常路径和 UI 验收仍须完成才能切换默认入口。

## 验证

`pnpm test:state-import` 启动固定生产基线的真实 Python 服务，使用临时 SQLite、隔离 PostgreSQL schema（未配置 `TEST_DATABASE_URL` 时使用 PGlite）及合成文件。它不使用生产数据、生产凭据或真实提供方。

三种身份/空间快照逐字段比较原 `/api/state` 的节点、素材和全部历史任务数组，包括顺序、空值、执行次数、执行节点/父任务、作者、参考及计时；另验证管理员不能读取他人个人空间、原默认工作区/图片开关、导出权限和凭据排除，以及源数据没有被导入修改。7 项检查通过，报告写入 `.runtime-advanced/state-import-parity/report.json`。素材文件为合成测试文件；媒体转码由独立的 `test:references` / `test:native` 覆盖。

`pnpm test` 增加 4 组回归：迁移/幂等/序列/节点权限、恶意或不完整归档拒绝、并发领取与轮询计数、早期数据库升级与未知信息保留。它们在真实 PostgreSQL 和 PGlite 均通过。完整平台 114 项测试、生成 91 项、估时 197 项及 148 组特征、计时 320 项对照通过。
