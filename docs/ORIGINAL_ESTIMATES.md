# 原估时查询

独立 Nest 原协议应用已实现 `POST /api/estimate`，返回原 `duration`、`queue` 结构。参数验证、素材授权、特征计算和排队预测均在 TypeScript/PostgreSQL 完成；Python 只作为隔离对照。默认 `/studio` 尚未接入这个应用，完整状态、画布、管理面及工作台 React 迁移仍需继续。

## 版本化能力

`originalEstimate: {version: 1}` 由 GPU `1.7.0`、Muse `1.6.0`、Flow / 兼容图片 `1.5.0` 提供。插件的 `prepare` 仅能调用工作区授权及参考素材读取回调，返回模型、参数与 UUID 引用。核心验证模型归属、生成类型和引用授权集合后，构造内存中的待估算任务，不创建数据库任务。

GPU 另声明估时节点资格 `eligible`：在线且已加载模型的忙碌节点仍参与估算。它与实际领取资格分开，避免把“当前不能领取”误判为“没有执行节点”。H3 原生输入沿用固定参考角色、声音选择和首尾帧比例规则；Breeze 使用原文字长度、语言及默认朗读指令。模型特征、资源与版本信息全部来自已安装插件和授权的服务端数据。

新版本仍需显式激活并升级连接，安装不改变现有任务或旧版本行为。远程 manifest 不能注册这项本地能力。执行连接选择与 [原生成接口](ORIGINAL_GENERATION.md) 一样要求无歧义；多个启用候选返回 503，不能随机选择。

## 保留原查询行为

- 估时与提交的规则不同：不要求余额、价格或已配置的执行凭据，不套用生成任务的引用数量、排队准入和素材包计费规则。被隐藏或停用的模型仍可返回估算及原 `model_paused` 排队原因。
- 参数类型和错误位置在登录检查前验证；业务参数与工作区的验证顺序保留原行为。H3 原生参考先检查工作区和素材，再检查生成参数；普通估时先验证参数，再授权工作区和素材。
- 在 PostgreSQL `REPEATABLE READ READ ONLY` 事务中读取一致的目录、队列、节点、健康状态与历史样本。没有轮询提供方、创建任务、冻结积分、容量预留、入队、续租或写入计时记录。
- 缺少执行连接时使用纯内存连接上下文，仍能查询目录的历史特征和原未知排队状态，不会凭空创建可执行连接。暂停的图片连接保留 `service_paused`；GPU 保留 `waiting_gpu`、`worker_update`、`no_instance` 等原原因。
- 预测会计入同一执行连接中其他工作区的前方任务，响应只返回待估任务的区间、原因和原节点编号，不包含其他工作区的提示词、素材或任务详情。真实调度仍由现有租约及 BullMQ/outbox 流程处理，预测不会预约资源。

## 验证

`pnpm test:estimate` 复用生成差分的临时原服务和隔离 PostgreSQL/PGlite。原服务派发关闭、连接为不可用的本地测试地址，不接触真实模型、支付或生产凭据。197 项真实 HTTP 对照覆盖默认参数、完整 Flow 目录、隐藏模型、参考素材、验证顺序、GPU 准备/在线/忙碌/暂停/过期/不兼容状态、Muse/Flow 健康缓存及图片暂停。148 组计时特征向量与不可变原估时函数构造的任务逐字段比较，避免仅以“没有历史样本”的空估算证明参数正确。

平台测试另覆盖无连接/无积分、并发查询、跨工作区前置任务、真实历史样本校准、运行中租约不变、伪造插件引用、远程注册拒绝及连接歧义。前后核对任务、账本、钱包、outbox、计时与容量记录。报告位于 `.runtime-advanced/estimate-parity/report.json`；共享估算算法和更广的调度状态仍由 `test:timing`、`test:queue` 验证。

这些结果证明本节覆盖的查询行为，不表示完整 `/api/state`、原提供方管理面、多通道 GPU 资源协议或整站 React 迁移已经完成。原 DOM、样式、静态素材与固定生产基线保持不变。
