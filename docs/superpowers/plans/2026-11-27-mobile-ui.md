# 移动端 UI 改版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 ≤760px 下把弗淼改成“顶栏 + 内容 + 底部标签栏”的 App 式布局，创作框改为贴底、可展开的底部面板，并统一首页、登录、工作台各页和画布列表的移动端视觉。

**Architecture:** 新增 `MobileChrome.tsx`（顶栏、标签栏）和 `ComposerDock.tsx`（创作框外层，只切换状态和 CSS，不重新挂载 `Composer`）。创作框展开状态放在 `Studio.tsx`，由点击和代码流程共同设置。所有移动端样式放在后加载的覆盖文件里，固定兼容资源不动。

**Tech Stack:** Next.js / React 19、TypeScript、纯 CSS 覆盖层、Playwright（`@playwright/test`）、`tsx --test`。

**Spec:** `docs/superpowers/specs/2026-11-27-mobile-ui-design.md`

## Global Constraints

- 断点：`max-width: 760px`；桌面（≥761px）外观和行为不变。
- 不修改 `baseline/production/static/*.css`，不新增依赖、路由、接口和数据结构。
- 新样式只用现有 CSS 变量（`--line`、`--text`、`--secondary`、`--muted`、`--composer`、`--hover`、`--focus`、`--danger`、`--pop`），浅色和深色都要正确显示。
- 尺寸体系：页面留白 16px；顶栏 52px；标签栏 56px（不含安全区）；页面标题 20px/600；分区标题 15px/600；正文 14px；输入控件 16px；卡片圆角 14px，面板圆角 20px；最小触控 44×44px。
- 固定栏处理 `env(safe-area-inset-top/bottom)`；软键盘以 `visualViewport` 为准，不用 `interactive-widget`。
- 目标浏览器：iOS Safari、安卓 Chrome 必须正常；微信内置浏览器尽量兼容。
- `apps/web` 只引用共享契约包；跨包引用用包名。
- 任何页面在 375px 下 `document.documentElement.scrollWidth <= innerWidth`。

## Review Focus

1. 很长的草稿（24 行）在收起和展开之间切换：内容、引用和光标都保留，收起态只显示一行，不撑高贴底栏。→ Task 2 测试 `long draft survives collapse/expand`。
2. 在创作框展开或抽屉打开时，把窗口从手机宽度拉到桌面宽度：桌面上不能残留遮罩、底部面板样式或标签栏。→ Task 2 测试 `widening to desktop clears mobile dock state`。
3. 团队空间名称很长：顶栏工作区胶囊截断显示，不挤掉头像，也不产生横向滚动。→ Task 1 测试 `long workspace name truncates`。
4. 深色主题下的新界面（顶栏、标签栏、底部面板、菜单面板）不能出现白底。→ Task 3 测试 `dark theme mobile surfaces`。
5. 从展开面板里点“从资产选择”，选完点“完成选择”后，回到创作页时面板仍是展开态，并显示新加的参考图。→ Task 2 测试 `reference picking returns to expanded dock`。
