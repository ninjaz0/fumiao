# Studio 内置模型接入

2026-11-27 · 设计稿，待负责人确认

## 负责人已确认的使用方式

管理员在 `/studio` 的「设置 → 模型接入」填写 OpenAI 兼容网关的接口地址和密钥，拉取列表，选中对话、图片或视频模型并定价上架。这项能力随 Studio 提供，管理员可以直接使用。

创作者选的是 Studio 模型。一个模型可以关联多个上游来源，全站共用一套售价，由管理员选定当前线路。接受请求时确定线路和价格。切换后的新请求走新线路，已经受理的请求按原线路执行和结算。

| 模型 | 管理员设置的售价 | 创作者支付的积分 |
| --- | --- | --- |
| 对话 | 每百万 Token 的普通输入、缓存命中输入、缓存写入、输出单价 | 每轮回复直接扣小数积分，在原对话里可查看该轮账单 |
| 图片 | 每张成图的积分 | 按成功产出并可供用户使用的图片张数结算 |
| 视频 | 每秒成片的积分 | 按交付成片的时长结算 |

缓存命中和缓存写入均可单独设价。两项各自留空时继承普通输入价，显式填零表示该项免费。首版支持复用已有「兼容对话」连接，由管理员设好新价格后主动切换。

## 上架方案与取舍

讨论过两种上架方式。按连接上架便于分别出售线路，但连接数量会直接反映在创作者的模型列表里。负责人选择按模型统一上架。首次接入仍然是勾选、定价。第二条线路由管理员关联。这样可以更换服务来源，并继续用原有模型打开对话、画布和历史账单。

公开模型 ID 标识 Studio 里的模型。线路记录连接、上游模型 ID、模型类型及支持的参数。两个网关返回同名 ID 时，后台提示已有候选，由管理员确认关联。也允许两家网关用不同的上游 ID 指向同一公开模型。改名、换线和价格修订都留在同一公开 ID 上。一个模型同时只有一条生效线路。线路不可用时显示具体原因，管理员可以重新选择。

## 从连接到第一次使用

1. **添加或复用连接。** 全站管理员输入 API 根地址及密钥，或选一个已保存的兼容对话连接。名称可由主机名生成。后端统一处理尾部斜杠，界面显示即将请求的模型列表地址。带路径前缀的 API 根地址按原前缀使用。
2. **拉取模型。** 宿主读取 `GET models`，识别出 OpenRouter 时一并读取 `images/models` 和 `videos/models`，按同一连接的上游 ID 合并。目录标明输出类型时预选用途，能读图的对话模型仍属于对话。标准目录有时只给出 ID，可搜索名称、多选并一次指定用途。网关缺少列表接口、目录漏列或密钥仅有调用权限时，可手动粘贴上游模型 ID。无效密钥、空目录、目录权限不足和超时分别提示。刷新时标出新增、缺失及有变动的候选，保留草稿、已发布线路和本地售价。[模型列表协议](https://developers.openai.com/api/reference/resources/models/methods/list) · [OpenRouter 图片目录](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) · [OpenRouter 视频目录](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)
3. **定价上架。** 对话的普通输入价和输出价、媒体的单位售价都支持显式零价，必填项留空则可保存草稿。首次上架同时保存定价、默认线路和目录状态。新增模型依现有全站及团队模型策略决定可见范围。原先已关闭的团队权限在接管时继续生效。「模型接入」负责这些模型的售价，原有模型管理和定价入口引用同一份生效数据。
4. **选用和换线。** 对话模型进入对话模型选择器，图片、视频进入相应创作入口和画布节点。估价、提交和 Worker 共享同一份公开模型及能力定义。关联线路要求模型类型一致。对于同类型的能力差异，建议列出变化并允许管理员确认切换。例如旧画布保存了 8 秒，新线只支持 4 秒，打开画布时保留原草稿，提交前指出具体节点和可选时长，让创作者决定如何调整。管理操作携带预期修订，并发编辑或报价过期时提示重新确认。

### 自建网关与批量上架

已知服务按其正式地址和公开契约带出调用格式。自建网关沿用管理员已确认的默认值。第一次添加视频时，若只读资料没有明确声明调用格式，页面用服务名称给出「New API（OpenAI 视频兼容）」和「OpenRouter 视频」。管理员可整批选一次、记作连接默认值，只有例外模型需要逐项改。两者都不匹配时可把该线路留作草稿，其余模型照常上架。模型名字、相同的接口路径和目录返回成功，都不足以证明创建、查询和下载遵循同一套约定。

发布时把实际调用格式、版本和模型能力存在线路上。更改连接默认值用于以后导入的模型。批量修改已上架线路时，管理员可先查看受影响的模型、画幅、时长及参考图选项，再确认生效。

页面默认列出已上架的 Studio 模型及当前线路，主操作为「接入服务」。可以给所选同类模型批量填价，也可逐项修改。目录返回的上游成本独立于 Studio 积分售价。给已上架模型关联另一条线路时沿用公开售价，默认存为备用，管理员点「切为当前线路」才接新单。对话默认展示普通输入和输出价，展开即可填写缓存命中和写入价，并用标明 Token 数的样例试算。图片和视频各自只需一个单位售价。

设置页分别显示「目录已读取」与这一版线路最近一次真实生成的结果。列目录、存草稿和发布只读取上游资料。若要在切换前验证一条备线，管理员可主动点「试用此线路」，从自己有生成权限的工作区确认样例输入和最高积分，经常规生成与结算流程提交一次。试用记录绑定这条线路的修订，普通创作者继续使用当前公开线路。

例如，管理员把一条上游线路作为「镜头预演」上架，定价 3 积分/秒。创作者选 8 秒时页面显示最高 24 积分，最终验收的成片若为 7.8 秒，这一单扣 23.4 积分。管理员随后关联另一家网关，再选用新线路。创作者仍选「镜头预演」。新线若只支持 4 秒，旧画布再次运行前会提示调整，已受理的 8 秒任务仍从原线取片。以上为体验演示用假设价格和参数。

## 复用旧连接和切换时点

在旧连接上选择要接管的模型，沿用其公开 ID、显示名和工作区权限。后台在原授权目的地复用加密凭据，浏览器只看见地址、连接名和密钥状态。草稿记录原连接及修订号，切换时重新校验。对于直接保存的密钥，在服务端为内置连接生成独立的凭据版本，以后由「模型接入」管理轮换。旧连接若借用图片服务密钥，页面会标出实际可复用范围。例如现有兼容对话包的这项授权仅覆盖原地址的目录和 `gpt-4.1` 对话。更换服务源或扩展用途时，管理员填写有对应权限的密钥。[现有凭据解析](../../../packages/platform/src/chat-providers.ts)

拉取模型和保存草稿期间，线上模型继续按原方式接单。旧的「积分 / 回复」可供核对，新的 Token 单价由管理员填写。确认切换时，同一事务校验草稿修订、连接状态及模型报价，然后发布新线路、价格版本及接管状态。按公开模型切换。同一旧连接中其余模型可以分次迁入。重复提交同一切换只生效一次。

以受理事务为界。切换前受理的聊天回合使用旧执行器和原定的每条回复价格。切换后，在同一对话发送的下一条消息按新快照结算。历史回合展示当时的固定价或实际账本金额，缺失的旧用量标为未记录。接管后的模型由内置设置管理，旧插件启停、升级和移除只能影响仍归其管理的模型及资源。待所有旧在途回合结算后再按现有流程释放旧资源。

## 首版协议范围建议

接口路径相对于管理员配置的 API 根地址。平台提供版本化的内置协议实现。插件目录仍由插件清单管理，新增内置模型直接登记在 Studio 模型目录。两种来源共用公开 ID、工作区授权、任务/回合和钱包。现有数据库中的连接、任务及运行中回合带插件外键或约束，实现时为内置来源建立明确的执行器版本和引用约束，历史任务继续按原版本解析。[目录注册](../../../packages/platform/src/catalog.ts) · [现有回合约束](../../../migrations/019_original_chat.sql)

| 类型 | 首版兼容契约 | 可交付结果 |
| --- | --- | --- |
| 对话 | `POST chat/completions`，默认流式并请求返回用量。仅支持完整 JSON 回复的网关可在线路选择整段返回。两种方式共用用量结算，有工具能力的模型沿用现有工具调用流程 | 一条可回看的回复和一张本轮账单 |
| 图片 | OpenAI 兼容线路用 `images/generations`，支持参考图编辑的线路用 `images/edits`。OpenRouter 图片专用目录中的模型用其 `POST images`，有参考图能力时传 `input_references` | 从图片数据或成品链接取得文件，验证后写入工作区私有素材，每张有效成品计一次。[OpenRouter 图片协议](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) |
| 视频 | 建议首版支持 New API 的 OpenAI Videos 兼容格式和 OpenRouter Videos。两条协议都覆盖文生视频，对声明支持首帧的模型开放单张首帧生视频 | 保存上游任务号及所需查询位置，按受理时的线路取成片，按实测时长结算 |

OpenAI 官方 Videos 服务于 2026-09-24 停用，New API 等网关仍发布兼容接口。接入范围以目标网关对外提供的协议为准。[对话流及用量](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) · [图片接口](https://developers.openai.com/api/reference/cli/resources/images) · [OpenAI 视频接口与停用说明](https://developers.openai.com/api/reference/resources/videos/methods/create) · [New API 视频路由](https://docs.newapi.pro/en/docs/guide/feature-guide/user/log)

可信的网关元数据或已有线路声明可以预填工具、参考图、尺寸及视频时长。只支持图生视频的模型在创作入口要求首帧，仅支持超分的模型可留作草稿。视频目录缺少时长时，可沿用该线路已确认的选项，或由管理员按网关说明为这批模型补充可选时长或有效范围。模型名字只用于提示用途。创作者看到的每一种可选组合都有线路依据和可展示的报价上限。

受理时保存公开模型、上游模型、执行器版本、线路与加密配置版本、价格版本、计费方式及输入参数。异步视频同时持久化上游任务号。Worker 重启后按既有任务号恢复查询与下载。提交结果不确定时沿用任务的待核查路径，避免重发产生第二笔上游订单。凭据遵守现有公网 HTTPS 及实际连接目的地检查。跨源媒体下载按既有匿名下载和私有资产权限规则处理。

在平台内，每种调用格式负责组装请求、解析回执和取得成品。排队、租约、下载重试、私有素材验收及钱包结算共用现有流程。线路能接收的参数取协议实现与模型能力的交集，包括哪些时长与分辨率可组合、能否用首帧。把有效组合交给现有模型表单，画布、估价和提交据此展示和校验。新增一种协议时，用固定样例核对请求、终态回执与成品，再将它加入内置可选格式。[模型表单契约](../../../packages/plugin-sdk/src/model-form.ts) · [任务执行与恢复](../../../packages/platform/src/executor.ts)

## 对话用量、价格和逐轮账单

按单次上游推理归一化，再汇总到用户看到的回复。对于总输入已含缓存的回执，普通输入等于总输入减去命中数和写入数。Chat Completions 在 `prompt_tokens_details` 里的 `cached_tokens`、`cache_write_tokens` 表示这两部分。DeepSeek 兼容回执也可从 `prompt_cache_hit_tokens` 读取命中数，未命中部分在没有独立写入明细时归普通输入。同时返回两种明细时只拆分一次。按缓存时长细分的写入合计为一项。缓存细项缺失而输入输出总量有效时，先拆出已知部分，余量归普通输入。负数、互相矛盾或明细超过总量的回执进入计量异常处理。[Chat Completions 用量](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) · [DeepSeek 缓存字段](https://api-docs.deepseek.com/guides/kv_cache/) · [Sub2API 定价表单](https://github.com/Wei-Shaw/sub2api/blob/dedeb65c1d4147c2a827b3b93d4f0e2f4241f12d/frontend/src/components/admin/channel/PricingEntryCard.vue#L102-L139) · [Sub2API 用量拆分](https://github.com/Wei-Shaw/sub2api/blob/dedeb65c1d4147c2a827b3b93d4f0e2f4241f12d/backend/internal/service/openai_gateway_usage.go#L147-L165)

示例中，上游报告总输入 10,000 Token，其中命中 7,000、写入 1,000，另有输出 500。管理员将缓存写入价留空。

| 明细 | Token | 积分 / 百万 Token | 小计（积分） |
| --- | ---: | ---: | ---: |
| 普通输入 | 2,000 | 100 | 0.2 |
| 缓存命中输入 | 7,000 | 20 | 0.14 |
| 缓存写入 | 1,000 | 100（随普通输入价） | 0.1 |
| 输出 | 500 | 400 | 0.2 |
| **本轮实扣** | | | **0.64** |

账单随助手回复展示，可在重开会话后查看。保存每项用量、当时单价、继承来源、小计和实扣金额，通过回合 ID 关联工作区积分流水。自动标题生成作为平台开销。一个回复有多次工具往返时，各次上游调用的最终用量各计一次，同一次流的累计事件只取最终有效值。重新传输、恢复或客户端重复提交都复用原回合的账单。用户主动重新生成会创建独立回合，原回复被替代后仍可从该轮记录打开原账单。账单访问沿用对应对话的工作区及资源权限。

## 钱包与异常结算建议

现有余额、冻结额、账本金额和余额快照按整积分保存。建议价格允许六位小数，以十进制定点保存和计算，钱包及流水精确到十二位小数。这样每百万 Token 的最小单价作用到单个 Token 仍能原值入账。金额对外继续以「积分」为单位，给新版客户端提供精确的十进制字段，既有数字字段继续支持原调用方。充值、退款、积分发放、预留、对账导出和预算统计使用同一计量单位。已有整数余额及历史金额按原值转换，支付订单的货币单位仍是分。[钱包与流水](../../../migrations/001_platform.sql) · [历史快照](../../../migrations/006_original_financial_history.sql)

- **受理。** 沿用工作区钱包的事务预留。建议普通对话沿用现有每次最多 4,096 个输出 Token 的默认值，按线路支持值和可用余额下调。以本次消息的输入估算、适用的最高输入价和明确的输出预算给出本轮扣费上限。工具需要再次请求模型时，在这一轮已授权的剩余额度内安排输入和输出。额度已用尽时提示原因。媒体按张数或请求时长预留。预留与最终实扣分开展示。[现有对话输出上限](../../../plugins/chat/src/policy.ts)
- **交付。** 在同一事务写入回合或任务的最终账单、扣款和余额快照，并释放剩余冻结额。建议图片按成功交付的张数计，成片时长取私有媒体校验结果并计至毫秒。用户实扣以已授权额度为上限。超出部分列出减免供对账。工作区并发请求遵守余额和已启用的预算约束。
- **未完成或缺少用量。** 建议沿用现有聊天的成功交付规则。用户停止、服务失败、中断或因额度不足而未完成回复时释放预留，回合账单显示原因和实扣零。成功交付且涉及多次推理时，建议只收有完整可信用量的调用，其余调用单列「用量缺失，未计费」。若整轮都缺少可信用量，保留回复并出具实扣 0 积分的账单。后台按线路列出缺失次数及最近发生时间，供管理员检查上游或调整回复模式。只有缓存细项缺失时仍按已知用量结算。未计费调用的上游成本由平台承担。
- **重试和恢复。** 同一业务编号只落一张最终账单。重放、超时后晚到的回执、并发结算和旧版本 Worker 重启均校验租约、来源版本及终态。数据库迁移先使存量快照和新执行模式可共存，再开放新受理。上线和恢复用同一版本的数据库、私有素材和密钥。旧版程序恢复采用切换前的一致备份。切换前后的正常任务按自身快照完成。

## 验收与实现边界

| 场景 | 可观察结果 |
| --- | --- |
| 管理员添加一个兼容网关，拉到三个类型的模型 | 选中、定价后成员可在对应入口使用。管理员刷新列表可继续添加。无权成员不能查看或修改连接 |
| 同一自建地址上的一批视频用表单接口，另一个视频用 JSON 接口 | 整批可一次确认常用格式，只给例外模型指定另一种。拉目录、保存和发布都产生零次上游生成请求。生成时检查两条线路各自的请求及取片方式 |
| 管理员在切换前试用已定价的备用线路 | 常规成员仍走当前线路。管理员看到试用的工作区、报价和真实结果。重复提交同一次试用时只结算一次 |
| 一个 OpenRouter 连接列出对话、图片和视频，另一条对话线路只返回整段 JSON | 图片专用目录的模型走图片接口并交付私有素材。两种回复方式按同一计量规则出账。对话模型的读图能力不会把它误列为生图模型 |
| 创建响应丢失，或取片时内容端点先返回临时错误 | 提交结果未知时显示待核查。已有任务号或成品回执时只恢复查询或下载。同源受权内容端点按协议携带凭据，签名外链匿名下载。每张成功账单可对到一份交付记录 |
| 连接只允许按已知 ID 调用，或目录中部分模型信息不全 | 可手动添加模型。确认所选用途、可用协议、必要能力和售价后即可发布。其余候选可留作草稿 |
| 两条线路提供同一模型，生成或聊天进行中换线并改价 | 成员只看到一个公开模型。已受理请求在原线路上按旧价完成，新的请求使用新线和新价。并发修改得到明确反馈 |
| 已受理的 8 秒视频遇上换线、改价、旧线停止接新单和 Worker 重启，新线只支持 4 秒 | 按旧凭据版本和任务号在原线取片，按旧价及该单上限只结算一次。原画布保留 8 秒，下一次生成前在该节点提示改为可用时长 |
| 旧连接有自有密钥或范围受限的借用密钥 | 可以复用已授权部分。新价格草稿和失败切换均不影响原受理。成功切换后旧对话可接着聊。已停用的团队模型不会因切换重新开放 |
| 成功的对话回执同时包含缓存命中和写入 | 上例逐项对齐并扣 0.64 积分。显式零价、继承价、缺一个缓存字段、多轮工具调用及重复终态回执各有确定账单 |
| 两张图片只交付一张，或下载一段有小数秒的成片 | 按交付数量或实测时长扣款，账本与资产一致。失败和重复下载可复测 |
| 老库含整数余额、冻结额、旧聊天、已有回执和在途任务 | 迁移、重启和恢复能核对原账面值。旧单按旧约定结算一次。不同工作区的账单、密钥和私有素材相互隔离 |

实施者负责表结构、接口命名、组件拆分、十进制序列化兼容和分阶段迁移，沿用仓库现有包边界与 `/studio` 验收流程。协议范围、精度、预留上限和异常收费属于本稿提出的默认选择，供负责人审批。自动选路、独立网关脚本和 Sub2API 的分档倍率属于后续独立需求。
