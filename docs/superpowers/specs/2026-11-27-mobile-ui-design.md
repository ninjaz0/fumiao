# 移动端 UI 与体验改版设计

日期：2026-11-27
分支：`aninjaz/optimize-mobile-ui`

## 意图

负责人在手机上打开弗淼时的反馈是“主页很丑，每个页面都很丑，创作框也没有按移动端适配”。在 390×844 视口实测（截图见任务记录）确认了以下问题：

- 工作台左侧常驻一条 64px 图标栏，占掉约六分之一屏宽，内容区被挤窄。
- 抽屉导航打开后，点击其他页面不会自动关闭（`Studio.tsx` 的 `navigate()` 只在点击当前页时关闭抽屉）。
- 创作框沿用桌面布局纵向堆叠：参考内容格子占 84×100px，参数按钮折成两行，发送按钮孤立在右下，状态提示另起一行，整个框占大半屏。提示词字号 14px，iOS 聚焦时会自动放大页面。
- 首页、登录、工作台、画布列表各用一套样式，顶栏、间距、字号不统一；首页基本是桌面版缩小。
- 资产页靠右下角“展开创作框”悬浮按钮切换，和创作页体验不一致；卡片操作按钮在 560px 下仅 26px，低于触控标准。

目标是让弗淼在手机上看起来、用起来像一个正经的移动应用。负责人在两个方向中选择了 **A · App 式布局**。

## 目标

1. ≤760px 时，工作台改为“顶栏 + 内容 + 底部标签栏”的 App 结构，去掉常驻图标栏。
2. 创作框在手机上默认是贴底的紧凑输入条，点开后展开为底部面板，包含完整参数；展开、收起都不丢草稿和引用。
3. 首页、登录、工作台各页（创作 / 对话 / 资产 / 队列 / 设置 / 插件页）和画布列表，使用统一的移动端尺寸体系：间距、字号、圆角、顶栏高度、触控尺寸。
4. 修复抽屉导航选完页面不关闭的问题。
5. 浅色和深色主题都正确显示。

## 非目标

- 桌面端（≥761px）的外观和行为保持不变。
- 画布编辑器内部的节点、连线、缩放等交互不重做；只让它的顶栏在手机上和整体风格一致。
- 不新增路由、接口、数据结构，不新增第三方依赖。
- 不修改 `baseline/production/static/*.css` 等固定兼容资源（字节和哈希属于兼容契约）。

## 反目标（技术上能用也算失败）

- 收起或展开创作框时丢失提示词、引用素材或参数，或者让 `Composer` 重新挂载。
- 底部标签栏或贴底创作框遮住页面最后一行内容、卡片按钮或弹窗按钮。
- 软键盘弹出时，固定栏在输入框上方乱跳，或挡住正在输入的内容。
- 任何页面在 375px 宽度出现横向滚动。
- 键盘和读屏用户在手机布局下失去现有的可达性：抽屉焦点约束、Esc 关闭、焦点归还、`aria-current`。

## 约束

- 断点沿用现有的 `max-width: 760px`（`Studio.tsx`、`ChatWorkspace.tsx`、`CanvasWorkspace.tsx` 和各 CSS 已统一使用）。
- 固定资源 `home.css`、`studio.css`、`canvas.css`、`chat.css` 只能通过后加载的覆盖样式修正，方式与现有 `studio-polish.css`、`auth-mobile.css`、`canvas-overrides.css` 相同。
- 新样式只使用现有 CSS 变量（`--line`、`--text`、`--secondary`、`--muted`、`--composer`、`--hover`、`--focus`、`--danger` 等），以便自动支持深色主题。
- `apps/web` 只能引用共享契约包，不引入新的 workspace 依赖（见 AGENTS.md 依赖方向）。
- 视口已经设置了 `viewportFit: "cover"`，固定栏需要处理 `env(safe-area-inset-*)`。
- **目标浏览器**（负责人确认）：iOS Safari 和安卓 Chrome 必须正常；微信内置浏览器尽量兼容，不能出现功能不可用，细小的视觉差异可以接受。软键盘处理以 `visualViewport` 为准：键盘弹出时隐藏底部标签栏，展开面板按可视区域高度限制最大高度，不依赖 `interactive-widget` 这类只有部分浏览器支持的视口参数。
- **验收方式**（负责人确认）：负责人在电脑浏览器的开发者工具中切换到手机模式，在固定验收实例 `http://localhost:3000/studio` 上检查，不需要把实例暴露到局域网。软键盘相关行为在开发者工具里无法完全模拟，交付时如实标注为未在真机上验证。

## 方案对比

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A · App 式布局（已选）** | 手机上去掉图标栏，加顶栏和 5 个底部标签；创作框像聊天输入框一样贴底，点开展开为面板；菜单改成底部面板 | 最符合手机使用习惯，拇指可达；需要新增导航组件、调整创作框外层状态，改动面和测试量更大 |
| B · 原结构精修 | 保留抽屉导航，去掉常驻图标栏，加汉堡菜单顶栏；创作框留在页面里，压缩成紧凑卡片 | 改动小、风险低；交互结构仍是桌面那套，只是更好看 |
| C · 只调样式 | 只改间距、字号、触控尺寸 | 最小改动，但解决不了“丑”和“框没适配”的结构问题，已排除 |

负责人选择 A，理由是要真正像移动应用，而不只是缩小的桌面版。

## 设计

### 1. 工作台外壳（≤760px）

```
┌──────────────────────────────┐
│ ☰  ◆  [管 个人空间 ⌄]     (头像) │  顶栏，约 52px + 顶部安全区，吸顶
├──────────────────────────────┤
│                              │
│           页面内容             │  左右留白 16px，无图标栏
│                              │
│ ┌──────────────────────────┐ │
│ │ [视频生成⌄][模型⌄][16:9·5s]│ │  贴底创作框（仅创作页、资产页）
│ │ (+)  描述你想生成的视频…   (↑)│ │
│ └──────────────────────────┘ │
├──────────────────────────────┤
│  创作   画布   对话   资产   队列  │  底部标签栏，约 56px + 底部安全区
└──────────────────────────────┘
```

- **顶栏**（新组件，放在 `Navigation.tsx`）：菜单按钮打开现有抽屉；品牌标记；工作区切换胶囊，复用现有 `workspaces` 弹层；头像按钮复用现有 `account` 弹层（设置、退出登录）。只在 ≤760px 显示。
- **抽屉**：保留现有 `.side` 抽屉，用于完整导航，包括插件页面（`studio_pages`）和设置。收起时在手机上完全移出屏幕，不再留 64px 图标栏，`.workspace` 去掉左边距。保留现有焦点约束、Esc 关闭、`inert`、焦点归还。**在手机上选择任意页面后自动关闭抽屉。**
- **底部标签栏**（新组件）：创作 / 画布 / 对话 / 资产 / 队列，复用现有 `nav` 常量、图标和 `navigate()`；当前页高亮并带 `aria-current="page"`。打开任务或图片详情、创作框展开为面板、对话页输入框聚焦（软键盘弹出）时隐藏。插件页和设置页时标签栏仍显示，但五个标签都不高亮。
- 画布标签沿用现有 `openCanvas()`，进入独立的 `/canvas` 页面。

### 2. 创作框（创作页、资产页、任务编辑）

同一个 `Composer` 实例，只通过外层包裹元素的状态和 CSS 切换形态，不移动 DOM、不重新挂载。

- **收起态（默认）**：固定在底部标签栏上方，圆角卡片带轻阴影。第一行是参数胶囊（创作类型、模型、参数摘要），可横向滚动；第二行是“+ 参考”按钮、单行提示词预览和发送按钮。隐藏参考素材格子、工具按钮、积分、预估费用和完整状态行（提示信息见下方“收起态的附加信息”）。
- **展开态**：点提示词区域、“+”按钮或参数胶囊时，展开为底部面板（最高约 85dvh，可内部滚动），面板上方是半透明遮罩，底部标签栏隐藏。面板里是完整创作框：参考素材、多行提示词（最小高度约 120px）、全部参数、积分和预估、状态提示。顶部有拖拽条样式的“收起”按钮；点遮罩或按 Esc 也会收起。生成成功后自动收起。
- **由代码把用户带回创作框时，一律打开展开态**（设计者决定：这些操作都表示用户接下来要编辑，收起态会让键盘盖在单行输入条上）。涉及的流程包括：“用作参考”（`useAsset` → `openHomeComposer`）、“编辑任务”（`editJob`）、“恢复刚才草稿”（`restoreDraft` → `returnToComposer`）、“图生视频”（`imageToVideo`），以及“从资产选择”后点“完成选择”（`finishPicking`）返回。因此展开状态放在 `Studio.tsx`，由这些流程设置，`focusEditor()` 在展开后执行。
- **收起态的附加信息**（设计者决定）：参数胶囊行只显示创作类型、模型和参数摘要。没有可用模型时，模型胶囊显示“前往配置生成模型”（管理员）或“暂无可用模型”，插件模型的内联 `ParameterFields` 只在展开态出现。只要 `composerFeedback()` 有 `status`、发送被 `submitReason` 禁用、需要“去充值”或可以“恢复刚才草稿”，收起态就在输入行上方显示一行提示（单行截断，优先级：禁用原因 > 充值 > 草稿恢复 > 进度），点击后展开面板。不修改 `composerFeedback` 的数据结构。
- 收起态高度因此可变：用 `ResizeObserver` 把贴底区域（创作框 + 标签栏）的实际高度写入 CSS 变量（如 `--mobile-dock-height`），页面底部留白和“不遮挡”规则都基于这个变量。
- 提示词在手机上用 16px 字号，避免 iOS 聚焦时放大页面。
- 创作页的页面内容（问候语、生成历史）底部留出贴底创作框加标签栏的高度。
- **资产页**用同一套贴底创作框，取代“展开创作框 / 收起创作框”按钮；保留多选时隐藏创作框、引用选择模式不贴底等现有规则。
- 任务详情里的编辑创作框（`JobDetail` 的 `composer`）沿用展开态面板样式，或保持内嵌，由实现者按实际布局判断，但不能出现横向溢出。

### 3. 弹层菜单在手机上改为底部面板

创作类型、模型、参数、工作区、账户等 `#popover` 弹层，在 ≤760px 改为贴底全宽面板（顶部圆角，带底部安全区，选项高度至少 44px），不再按触发按钮定位。`positionMenu()` 在手机上跳过坐标计算，或者由 CSS 覆盖。焦点进入和归还逻辑保持不变。

### 4. 统一的移动端尺寸体系

新增 `apps/web/studio/studio-mobile.css`，在 `Studio.tsx` 中于 `studio-polish.css` 之后引入，集中放置 ≤760px 的工作台规则，并定义以下变量：

| 项目 | 取值 |
| --- | --- |
| 页面左右留白 | 16px |
| 顶栏高度 | 52px |
| 底部标签栏高度 | 56px（不含安全区） |
| 页面标题 | 20px / 600 |
| 分区标题 | 15px / 600 |
| 正文 | 14px；输入控件 16px |
| 卡片圆角 | 14px；面板圆角 20px |
| 最小触控尺寸 | 44×44px（视觉更小的图标按钮用扩大的点击区域） |

`studio-polish.css` 里已有的 760px 规则如果和新体系冲突，迁移到新文件统一维护，不留两处互相覆盖。

### 5. 各页面要点

- **创作**：问候语改为 20px，左对齐，上边距收紧；生成历史为两列网格；空状态更矮，不再是一大块虚线框。
- **资产**：分类和筛选改为可横向滚动的胶囊条；网格两列；卡片操作按钮至少 36px，点击区域 44px；多选工具条贴底，位置在标签栏之上。
- **队列**：任务行改为卡片，主信息（类型、状态、进度）在第一行，时间和 ID 在第二行。
- **对话**：内容区填满顶栏和标签栏之间的高度；会话列表沿用现有的窄屏浮层（`historyOverlay`）；输入框贴底，聚焦时隐藏标签栏。
- **设置**：分类导航改为页面顶部可横向滚动的标签条（或列表进入详情，由实现者按现有 `SettingsShell` 结构选择改动较小的一种）；表单控件占满宽度；宽表格在手机上改为堆叠卡片或横向滚动容器，页面本身不能横向滚动。
- **插件页**：外层容器遵守留白和无横向滚动；插件内部内容不做定制。
- **画布列表（`/canvas`）**：顶栏改为与工作台顶栏一致的高度、字号和返回按钮样式；“剧集项目树”说明卡片压缩为一行标题加折叠说明；“新建画布”按钮和分段切换使用统一尺寸。
- **画布编辑器**：只统一顶栏（高度、返回按钮、标题截断），其余不动。

### 6. 首页（`/`）

新增 `apps/web/home/home-mobile.css`，在 `Home.tsx` 中引入，只包含 ≤760px 规则：

- 顶栏：品牌、主题切换、“进入工作台”；未登录时的“登录”文字链接在 ≤380px 时并入主按钮区域或隐藏，保证一行放得下，不挤压品牌。
- 首屏：标题约 32px，行高收紧；导语 15px；两个 CTA 纵向堆叠并占满宽度；示例画布等比缩小，节点间距和内边距收紧，确保首屏能看到标题、导语、主按钮和示例画布的上沿。
- 下方各区块：区块上下间距减半；功能列表改为带图标的卡片；步骤列表编号与正文对齐；结尾 CTA 和页脚收紧。

### 7. 登录 / 注册

在现有 `auth-mobile.css` 上调整：卡片在手机上去掉外框和阴影，内容贴近全宽；输入框字号 16px、高度 48px；顶部品牌横幅高度收紧；整体垂直方向略微居中，不再有大面积留白。

## 测试与验证

- 更新现有浏览器测试中依赖旧手机布局的部分：
  - `tests/integration/studio-nest-browser.ts` 的 `checkMobileSidebar`：“展开侧边栏”按钮改为位于顶栏，抽屉的焦点约束、Esc 和焦点归还断言保留。
  - `tests/integration/mobile-asset-composer-browser.ts`：改为验证贴底创作框的收起和展开、长草稿在两种状态间不丢失，以及原有的卡片四角点击不被创作框遮挡。
- 新增手机布局浏览器测试（375×667，触屏）：
  - 底部标签切换页面，`aria-current` 正确。
  - 从抽屉选择页面后抽屉自动关闭。
  - 创作框收起和展开时，提示词与引用保持不变；Esc 和点遮罩都能收起。
  - 首页、登录、创作、对话、资产、队列、设置、画布列表在 375px 下 `document.documentElement.scrollWidth <= innerWidth`。
  - 页面最后一个可交互元素滚到底部后，不被标签栏或创作框遮挡。
- 桌面回归：1440×900 下各页面截图与改动前对比，没有可见差异。
- 改动前后在 390×844 下截取各页面浅色和深色截图，作为验收材料。
- 按 AGENTS.md 运行 `pnpm lint`、`pnpm typecheck:web`、`pnpm test`、`pnpm build`、`pnpm test:studio`。

## 留给实现者决定的部分

- 新组件的具体拆分和命名，以及创作框展开状态放在 `Studio.tsx` 还是外层包裹组件。
- 设置页手机导航采用横向标签条还是“列表进入详情”，选改动较小的一种。
- 弹层改底部面板采用 JS 分支还是纯 CSS 覆盖。
- 各页面的具体像素微调，在上面的尺寸体系内取值。
