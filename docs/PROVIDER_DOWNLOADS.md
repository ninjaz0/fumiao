# 提供方成品下载

Muse `1.8.0`、Flow `1.7.0` 新增本地版本化 `artifactDownload: {version: 1}`。这些版本继承原生成、估时、状态能力，安装不自动激活目录、升级连接或改变已接受任务。默认工作台和业务后端未切换。

原实现对成品地址的处理与通用 URL 下载不同：Muse 将公开地址、旧域名及相对媒体路径映射回已配置的后端，并携带鉴权；Flow 将后端/公开缓存路径映射回后端，其允许的 Google 媒体地址不携带连接密钥。新插件实现这些规则，连接可选 `publicUrl` 对应原公开入口配置，默认仍为原 `/muse`、`/flow` 入口。

下载能力仅向已安装本地适配器开放。执行器使用任务冻结的插件版本和加密配置快照，调用插件下载后继续做媒体校验、私有保存和一次结算。新能力按插件规则决定地址与鉴权，不在业务核心新增提供方名称条件；旧版本保留原通用传输路径。远程 HTTP 插件暂不能声明该能力。

两种插件均不跟随重定向，流式累计最多 64 MiB；Muse 网络读取超时 45 秒，Flow 90 秒。读取有进展时刷新空闲计时，外层执行取消仍会终止读取。Muse 下载中断保留已接受回执及保存阶段的计时，释放本次租约后只重试下载；不会重新生成、增加尝试次数或重复计费。明确无效地址和超限会失败并一次退款。Flow 下载失败保留原首次保存/恢复保存的不同错误文案并结束任务。

`pnpm test:downloads` 用临时目录运行固定原 Python 下载函数，替换全部 HTTP opener，不访问任何提供方。609 个地址、鉴权、超时参数及错误案例逐项比较，涵盖后端路径前缀、公开/旧域名、相对路径、文件名长度、路径穿越、查询/片段、Google 子域、用户信息、端口和 URL 规范化差异。报告写入 `.runtime-advanced/download-parity/report.json`。

平台三组测试使用本地 HTTP 假服务：Muse 首次下载失败后只保存同一回执、Flow 失败只退款一次且不将密钥发向 Google、超限/重定向拒绝，以及旧 Muse 版本恢复原传输。素材和数据库均隔离，不使用生产凭据。

本阶段仅迁移下载协议；后续 Muse `1.9.0`、Flow `1.8.0` 的版本化格式/方向/像素验收见 [提供方成品验收](PROVIDER_MEDIA.md)。Muse/Flow 完整提交与轮询错误、资源池和原管理界面仍待迁移，不能凭这些下载测试宣称提供方或整站迁移完成。原 DOM、CSS、素材和基线文件保持不变。
