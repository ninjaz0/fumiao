# GPU 节点与生成参数

## 输入冻结

SDK 的 `inputPreparation: {version: 1}` 要求本地插件提供 `referenceIds`、`prepareInput`，并为每个模型声明 `preparedSchema`。远程 manifest 不能注册这项能力。平台在提交事务中读取同一工作区的可访问素材，插件只能获得媒体类型、尺寸、大小和参考信息，不能获得对象路径、密钥或数据库连接。返回引用必须属于已授权集合，冻结参数还须通过结果 schema。

- H3 保留首尾帧槽位、图片比例检查、自动比例选择、各质量对应尺寸、随机种子和声音引用选择。原生模式最多 9 图、3 视频、3 音频，总计 12 个；同类音视频总时长上限与原版一致。
- 音视频时长、帧率、声音信息来自参考上传时保存的 PostgreSQL 元数据，客户端不能提交伪造的 `h3_inputs` 或尺寸。缺少历史参考元数据时要求重新上传，不能从旧文件清单补造。
- 按顺序冻结文件和角色；以后编辑素材包或元数据不会改写任务。普通图片模式保留原版允许重复引用的行为，数据库仅保存一次素材关联。
- Breeze 冻结中英文默认朗读指令和种子。`1.6.0` 的 Studio 协议适配在授权后统一转换身份，再复用同一个原子任务接受事务。

## 执行与验收

`artifactValidation: {version: 1}` 仅支持已安装的本地 pull 插件。`validateArtifact` 返回媒体元数据及可选计时报告，平台仍在最终事务中复核节点和租约，保存私有成片并结算。并发重复回传只产生一份资产和一次扣费；验收过程中租约失效则清理暂存对象，不能结算。

节点执行端使用 `/agent`，按授权路径下载素材。桥接器将图片转为 PNG，视频和音频按原 MP4/WAV 字节暂存，传递冻结的原生清单；渲染器必须返回清单指纹，桥接器不会自行伪造成片证明。`X-Sha256` 与 `X-Job-Timing` 携带摘要、采样步数、快速模式及有限计时字段，不发送本地路径或提供方原响应。

- H3 验证输入指纹、采样步数和快速模式，再验证摘要、尺寸、旋转、H.264、24 fps、帧数、AAC 双声道 32 kHz 和时长，并完整解码。帧数映射保持原版的 124 / 243 / 362。
- Breeze 验证 PCM WAV、单声道、16 bit、24 kHz、完整帧、时长和振幅，保留原错误文本。计时头的解析和无效字段处理与原 Pydantic 契约对照。
- `1.5.0` 成片上限为 64 MiB；旧版执行器的本地绝对上限仍是 128 MiB。每个 API 进程同时最多验收 2 个成片，超过返回 503；worker 从已保存结果重试，不重复渲染。
- FFprobe 15 秒、完整解码 90 秒超时，子进程限协议、输出及线程，临时目录和文件保持私有并在结束后清理。平台的验收取消信号也会终止子进程。
- worker 观测实际采样进度，并沿用原单调时钟记录准备、生成和收尾区间。恢复缓存标记为 `recovered`，不会成为正常耗时估算样本；未观测到的区间和冷启动状态不补造。计时、成片和账本在同一结算事务保存。
- 不可恢复的 400 / 413 / 422 回传拒绝会停止 worker 心跳并保留本地回执，等待核对；临时 429 / 5xx 从现成结果重试。

## 激活与节点声明

按 [插件升级](PLUGINS.md#升级与停用) 显式升级连接到 `1.5.0` 并激活目录，复核后启用。GPU 推理仍运行在独立 Python / CUDA / ROCm 环境，不能把推理运行时与临时 Python 业务 API 混为一谈。桥接器使用预先安装的模型，不下载或安装模型资产。

节点用 `--capabilities /path/to/verified-capabilities.json` 声明已验证的运行时。H3 原生参考要求以下 workflow；采样步数只填写该机器实际支持的值：

```json
{
  "context": {"workflow": "h3-v6-native-inputs-turbo4"},
  "queue": {
    "stage": "ready",
    "ready_models": ["MiniMax H3"],
    "video_steps": [4, 16, 20, 32, 50],
    "can_accept": true
  }
}
```

worker 自动生成本次运行的 `runtime_id` 并报告忙闲状态。当前为串行执行端，不提供完整多通道资源计划、自动模型装卸、桌面安装器、Colab 调度或原节点收益协议；这些仍需后续迁移和真实运行环境验证。
