# 原图片设置与连接探测

图片插件 `1.8.0` 增加 `originalImageSettings` version 1。插件声明旧接口命名空间、默认模型与联动模型，并实现只读探测；原 API 适配层处理身份、输入验证、模型策略、公开配置与审计。提供方的地址、凭据、HTTP、解析和错误分类不进入核心设置服务。

独立 Nest 应用已提供 `PUT /api/settings/openai` 和 `POST /api/settings/openai/check`。它们仍使用原路径与响应，未切换默认 `/studio` 后端，也未修改原页面。

保存请求保留原 `enabled` 的宽松布尔解析和 `default_model` 字面量验证，验证发生在端点认证之前。每次保存都递增全局模型修订号，即使值相同；只改变插件声明的原联动模型，隐藏模型仍强制关闭。随后根据全部图片模型重新计算全局图片状态，不直接把请求中的布尔值当作最终公开状态。设置、模型修订、图片开关和审计在同一事务中完成。凭据不从这个旧请求写入，也不出现在响应中。

“测试连接”仅管理员可调用，使用当前配置向原单模型 URL 发 GET，30 秒读取空闲超时、64 MiB 响应上限。任何可解析 JSON 都算成功，不擅自要求模型清单或指定字段；HTTP 错误保留原优先级和固定中文说明。原来未捕获的畸形 JSON / 错误结构继续返回原普通文本 500，使前端保留原兜底文案。探测不修改模型开关、健康快照、积分或任务，不持有数据库事务等待网络。

原协议要求一个活动目录版本对应至多一个提供方连接。没有连接时返回未配置；存在歧义时拒绝选择任意凭据。插件需显式激活，既有任务仍保留其版本与冻结配置。远程插件不能冒充这个本地兼容能力。

`pnpm test:image-settings` 使用临时 SQLite 的原 FastAPI 应用和本地模拟提供方，对照隔离 PostgreSQL / PGlite 的 84 个 HTTP 场景，同时比较返回体、状态、Content-Type、Allow、策略修订、图片开关和提供方调用。平台测试另覆盖并发保存、不改变无关模型、隐藏模型、事务回滚、连接歧义、无生成任务及旧插件隔离。所有请求使用合成配置，没有访问真实提供方。

本阶段补齐图片管理接口。原 Muse / Flow 服务配置来自服务端环境，不存在对应的同名页面写入接口；独立 Advanced 连接管理继续由插件配置契约承担。对话提供方的管理与会话、贡献节点/资源池、支付/画布等剩余原业务及工作台 React 迁移仍待完成。默认工作台仍连接 Python 兼容 API，不能据此宣称整体迁移完成。
