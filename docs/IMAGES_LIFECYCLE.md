# 图片生成执行与恢复

`compatible-images` `1.7.0` 使用本地 `requestLifecycle` version 3，继承原提交、估时、状态与队列能力。协议、图片检查和原错误说明在插件中实现；平台统一处理授权、租约、私有存储与积分。旧版本和已接受任务不会自动升级，默认 `/studio` 未切换。

## 请求与结果

生成使用冻结配置、有序参考文件和原参数：模型、提示词、大小、质量、`n: 1`、PNG 格式及原身份适配层生成的 safety identifier。Unicode `<Picture 数字>` 转为原“参考图片数字”；编辑上传保留 `image[]`、从 1 开始的文件名、JPEG 的 `.jpg` 扩展名及 multipart 末尾换行。不添加原接口没有的 Idempotency-Key。

HTTP 使用原 600 秒读取空闲超时，接收最多 64 MiB JSON；允许原 POST 301/302/303 转 GET，307/308 不重发 POST。错误体最多读取 64 KiB，按原额度、密钥、组织验证、审核、频率、权限、参数顺序返回固定说明，提供方原始错误不进入界面。断线直接失败、退款一次，不自动重发或进入 Muse 的退避流程。

只接受一项字符串 `b64_json`，远程图片 URL 不作为备用结果。严格 Base64 解码后检查 32 MiB 上限，再在有界工作线程中检查 PNG、3200 万像素、块校验和首帧完整解码。按原 Pillow `verify` 语义检查至 IEND 头，不检查其 CRC；原始宽高不因 EXIF 方向交换。保存原文件字节，不转码。该验收模式独立于 Muse / Flow 的图片检查。

`x-request-id` 和 usage 保存为 `result.providerResponse` version 1。usage 采用 JSON 文本保留 null、数组、标量和非有限数，不把请求追踪编号当成可轮询任务编号。该信息是服务端执行记录，不新增 UI 字段。

## 队列与事务

每个连接串行 FIFO 执行，保留模型权限、全局图片开关和配置有效性检查。停用账户的排队任务只在服务可运行时取消。参考元数据必须在领取事务中仍存在且属于当前工作区；缺失时保持 queued、零尝试且无计时记录，与原领取回滚一致。已领取任务保留同一元数据快照，文件读取失败按原处理说明失败并退款。

成功产物的素材行、关联、计时结束、积分结算及任务终态在同一 PostgreSQL 事务内提交。私有对象上传后若事务失败，删除本次对象，避免失败任务遗留可见图片或扣费。失败及重复执行只释放一次冻结积分。

图片生成是同步、不可恢复的请求。租约过期或再次领取已运行任务时，即使持久化了响应，也按原重启说明失败；计时为 interrupted，并保留内部结果不确定标志。不会重新请求或继续保存。version 3 另声明执行总时限；图片插件由自身读取空闲计时控制，不受通用 15 分钟总时限截断。

## 验证与边界

`pnpm test:images-lifecycle` 在临时 SQLite 中直接运行固定的 `image_api.run_one`、`provider_call`、Pillow 和原计费触发器，对照隔离 PostgreSQL / PGlite 的 214 个场景、55 个合成格式文件。覆盖原请求与 multipart、JSON 编码、错误优先级、畸形数据、严格 Base64、PNG CRC / IEND / EXIF / APNG、尺寸、响应大小、文件读取失败、参考缺失、计时和退款；成功输出逐字节比较。没有调用真实提供方或使用生产凭据。

平台测试另覆盖 FIFO、重复执行、失效配置、重启前后、原重定向规则、停用账户、存储失败、结算事务回滚、32 MiB 图片解码及非有限 usage。共享 JSON 解码器改用原生快路径和线性字符串扫描，避免大 Base64 响应触发正则栈溢出；Muse / Flow 原差分测试保持通过。

当前完成图片提供方的执行路径。原管理端 `/api/settings/openai` 和 `/check`、其他提供方配置、贡献节点/资源池、对话与其余业务及工作台/画布 React 迁移仍须继续。默认入口仍由 Next 承载原工作台并连接 Python 兼容 API；这不是整体技术栈迁移完成，也不允许把新旧会话或数据库直接混接。
