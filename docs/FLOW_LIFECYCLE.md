# Flow 流式生成与恢复

Flow `1.9.0` 使用本地 `requestLifecycle` version 2，继承既有原提交、估时、状态、下载和媒体验收能力。平台统一管理租约、私有存储和积分；Flow 的 SSE、错误说明、请求头及结果选择由插件实现。安装不自动升级既有任务或连接，默认 `/studio` 未切换。

## 原执行行为

请求保留模型 upstream 编号、原提示词、有序图片 data URL、冻结的 `extend://` 来源和 `stream: true`。根据公开服务地址发送 `X-Forwarded-Host` / `X-Forwarded-Proto`，使用服务端冻结凭据；不跟随生成重定向。读取采用背压和有限缓冲，8 MiB 上限按原 SSE 行计算，流内读取空闲超时为 600 秒。

SSE 只处理字节前缀 `data:`；无效 JSON 行跳过，`[DONE]` 立即结束，保留最后无换行的事件。`delta` 只在缺省时回退到 `message`，非字符串内容不拼入结果；诊断文本只参与安全错误分类，不作为成品地址。生成类型决定匹配视频标签还是 Markdown 图片，其次取最后一个普通 URL。只有标签/Markdown 捕获地址进行 HTML 解码，普通 URL 保持原字符串。

HTTP 错误最多读取 64 KiB 后按原优先级映射固定中文文案：异常活动、密钥、验证码、账户、额度、内容审核、频率及参数。普通断线使用原“生成结果未确认”文案。上述运行错误直接失败并退款一次，不自动重发，不套用 Muse 的 60 秒退避。

每个连接串行领取最早的可运行任务，即使连接并发配置大于 1 也不并行调用 Flow；模型关闭、工作区权限、失效账户仍限制领取。原 Flow 不依赖全局图片开关。提供方不可用时保留原排队说明，不增加新的等待文案。

## 进度和中断

有效事件最多每 8 秒更新一次固定“Flow 正在生成”说明、任务更新时间和健康快照。更新必须持有当前有效租约，且仅在连接凭据/版本与任务冻结配置一致时更新该连接健康；凭据变更后旧任务不能把新配置标为就绪。活动 Flow 请求期间不另起周期性探测；进度更新会使先前探测失效，避免旧结果覆盖刚确认的健康状态。

已经取得成品的回执先持久化，再执行私有下载和验证。进程中断后复用回执保存，不重复生成、不重读参考图，并保留同一计时记录。恢复保存失败使用原独立说明；存在待保存结果时，先处理保存再取消停用账户的排队任务。Flow 的排队取消不增加原本不存在的计时记录。

无成品回执的派发租约过期使用原服务重启说明，计时记为 interrupted，任务失败并退款一次，同时保留内部不确定标志。运行断线与进程重启分别保留 failed / interrupted 计时语义，旧 Flow 版本的通用执行行为不改变。

## 验证

`pnpm test:flow-lifecycle` 在临时 SQLite 中直接运行固定原 `flow_provider.tick`、`generate`、`complete` 和积分触发器，对照隔离 PostgreSQL / PGlite 的 76 个场景，包括错误、畸形/分片 SSE、`[DONE]`、Unicode、地址选择、参考和续写请求、成品保存及退款。HTTP 由本地假服务替代；原产物下载和媒体检查在该队列测试中使用确定的合成结果，真实格式验证仍由 `test:provider-media` 独立覆盖。

同一命令另比较 210 个原安全错误映射和 2400 个 HTML 解码结果。HTML5 名称数据来自 Python 3.12 `html.entities`，来源和许可证见 `plugins/flow/html5/`。历史隐藏图片模型仅在隔离测试夹具中启用，用于保留旧任务执行能力；产品目录及隐藏设置未修改。

平台测试覆盖串行 FIFO、重复执行、冻结配置、旧租约拒绝、进度与健康、停用取消、失联恢复、回执复用、错误区别、一次积分结算、远程能力拒绝，以及 Muse version 1 不受 version 2 改动影响。另有真实 PNG 贯穿同一版本的 SSE、鉴权缓存下载、解码检查和私有保存，验证原字节与参考素材角色。没有使用生产凭据，也未调用真实提供方或支付。

本次范围是 Flow 服务端 HTTP 生成路径。原贡献节点/资源池的 `has_ready_flow` 路由、桌面客户端和完整资源管理仍待迁移，不能将该连接单独接入默认工作台。图片提供方异常路径、其他业务以及工作台/画布 React 迁移也未完成；当前仍是整体迁移中的一个已验证阶段。
